## 4. IM 软件接入（难点 3）

### 4.1 通道实现（两类真实 SDK）

| 通道 | 判定 | 证据 |
| --- | --- | --- |
| **企业微信** | ✅ **真实 Conn** | `wecom/conn.go:73 NewConn` 用 `aibot.NewWSClient` + `Connect()`；SDK 内部 `websocket.Dial` + `WSS wss://openws.work.weixin.qq.com` + 心跳 + 重连（真实长连接非桩） |
| **飞书** | ✅ **真实 Conn** | `feishu/conn.go` 用 larksuite `ws.Client` + `OnP2MessageReceiveV1` + OpenAPI `im/message` |
| 微信客服/公众号/Telegram | ❌ 未实现 | 仅 `docs` 提及；验收标准要求"至少两类且含微信或企业微信" → **已满足** |

**两类通道差异（验收标准 3）**：
- **鉴权**：企微 WSS 长连接 `aibot_subscribe`（botID+secret）vs 飞书 WSS 长连接 + webhook 模式需 `verification_token` 验签
- **回复寻址**：企微 `msgtype=text` 主动推送**不支持**（`40008`）→ 改用 `SendMarkdown`/流式；飞书统一 `receive_id_type=chat_id`（单聊 p2p 也有稳定 `oc_xxx_p2p`，避免依赖 sender `open_id` 权限）
- **群聊 @ 判定**：企微靠 SDK 文本；飞书按 `Mention.Id.OpenID/UnionID`（Key 是位置占位符非身份），`fetchBotOpenID()` 失败时接受群消息兜底不静默丢弃
- **去重**：企微重推由"收到即开流占位"阻止（`wecom/conn.go:89-98`）

**❌ G18（P1，仅文本）**：`wecom/conn.go:83` **只注册 `OnMessageText`**，图片/文件/语音/事件帧在 SDK 回调层直接丢弃（`conn.go:16-17` 注释自认），用户发图**无任何回执**。

### 4.2 消息转换链

- **入站**：IM 原始帧 → `Adapter.Start` 归一化 → `channels.InboundMessage` → `gateway.pumpInbound` → `bus.Message`（`Content: model.NewUserMessage`）→ worker `runner.Run`
- **出站**：Agent `event` → `finalTextWithUsage`（`worker.go` 汇总文本+tokens）→ `bus` outbound → `gateway.Run` 按 session+channel 分发 → `Adapter.Send` → 平台化（流式/卡片）
- Kind 支持：`channels.go:28-29 KindCard/KindStream`；企微流式占位 + 同 `stream.id` 原位替换（`wecom/conn.go:163-188`）

**❌ G19（P1，占位流错位）**：`Conn.pending` 是 per-target FIFO；若某轮 run 失败（worker 不产生 outbound），**占位永不 finish**，下一条回复会顶替旧占位 → **回复与消息错位**。

### 4.3 绑定、去重、身份映射

✅ 绑定：`channel_bindings`（`uk_channel_account(channel,account_id)` 全局唯一）；`ChannelAPI.create` 校验 **agent 必须同租户**（`channel_handler.go:113-123`）；凭证走 secret store（`{tenant}/{channel}:{account}:secret`）
