# 灰度发布与配置回滚策略

> 状态：策略 + 部分实现（阶段 33，需求验收 D3）。
> 已实现代码：Agent 不可变版本发布/回滚（domain/agent + agent_versions 表 +
> web rollback API）；租户配置版本历史 + 回滚 API（tenant config 版本快照 +
> `tenant_config_versions` 表，`deployments/mysql/init/011_*.sql`）。
> 未实现（策略明确不做）：按百分比切分流量的 canary——原因见 §4。

## 1. 两级可回滚对象

| 对象 | 粒度 | 机制 | 回滚 |
| --- | --- | --- | --- |
| **Agent 运行配置** | 单 agent | 不可变版本：发布即生成 `agent_versions` 新版本（draft→published），原子切换 | `Rollback(ctx,id,version)`（agent.go:130-135）+ `POST /agents/{id}/rollback`（agent_handler.go:165）；存储支持 COALESCE(MAX(version)) 分配（agentstore） |
| **租户配置** | 单租户 | 每次 PUT 生成配置快照版本 | `GET /tenants/{id}/config-versions` + `POST /tenants/{id}/config-rollback {version}`（tenant handler）；表 `tenant_config_versions`（011 SQL） |

回滚动作本身也是“写”，会生成新的头部版本（agent 回滚到 v1 会产生 v3 状态；
租户同理），保证审计上“现在是什么”永远可查。

## 2. 租户配置回滚 API（本次新增）

每次 `PUT /tenants/{id}`（web/tenant_handler.go update）成功后，`Manager.Update`
把**更新后**的完整租户 JSON 写入版本表（tenant.go `SnapshotConfig`）；版本号
每租户单调递增（MySQL 用 `COALESCE(MAX(version),0)+1`，撞唯一键重试）。

- `GET /tenants/{id}/config-versions` → 历史（新→旧，含 config 与 created_at）；
- `POST /tenants/{id}/config-rollback {version}` → 校验存在 → 应用该快照 → 落新
  版本 → 返回恢复后的租户。

影响面：DataBackend（切换数据后端）、Quota（预算）、AuditPolicy（脱敏/白名单/
强制审批）全部可回退。**回滚后 worker 下一轮消息自动按新策略运行**（治理策略
每次 handle 从租户表重新解析，无缓存）。

## 3. 灰度发布的现实形态（IM 场景）

对 IM 机器人，“按 % 切流量的 canary”与**单会话上下文连续性**冲突：同一会话的
多轮对话必须由同一 Agent 版本服务，否则状态/记忆错位。因此平台灰度采用：

1. **新版本先在受控范围验证**：Agent 处于 `draft` 阶段只对内部会话/测试会话
   可用（BuildAgent 用当前 published profile）；
2. **发布 = 原子切换**：`Publish` 一次把新 RuntimeProfile 立为当前版本（记录
   旧版本），失败即 `Rollback` 旧版——会话级切换，天然无跨版本混合；
3. **租户级灰度**：若不同租户可用不同 agent 版本（binding 指向不同 agent），
   逐租户 Publish 即“按租户灰度”；平台无全局单版本，故无 A/B 混流问题；
4. 未来若出现 Web 控制台多用户共享场景需要按 % 切流，才需在 route 层加
   `percent` 分流键（当前 IM 无此需求，不实现）。

## 4. 为什么不做百分比 canary

- 需求原文“说明如何做灰度发布和租户级配置回滚”是**策略说明型**要求，核心是
  “可验证发布 + 可回退”，版本化机制已覆盖；
- 代码中全仓无 `percent`/分流字段（验收时确认）——按 % 切分会破坏会话状态
  连续性且引入一致性难题；结论写入本文（ADR 倾向），如产品明确需要再评估。

## 5. 操作建议

- 改租户治理配置前先 `GET /tenants/{id}` 保存当前值（或直接用 config-versions
  最近版本号做回滚目标）；
- 发布 Agent 后保留上版：`agent_versions` 已存全部历史版本，勿清理最近 N 个
  以便快速回滚。
