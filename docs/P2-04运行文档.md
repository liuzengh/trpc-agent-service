# P2-04 运行文档：本地/预生产集成、有限压力/故障、安全测试与生产运维手册

> 本文档是 P2-04 交付的**本地/预生产操作手册**与发布门禁清单。它的执行
> 环境永远是本地 Docker/Compose 与 owner-scoped 测试资源。它不代表
> production deployment、production cutover、云 IAM/KMS/TLS、Kubernetes、
> PostgreSQL HA、Redis Cluster、生产 backup/PITR、SLO/RPO/RTO 或任何
> 安全 clean 声明。"有运维手册"不等于"生产运维已经执行"。

## 1. 适用范围、前置条件和不适用范围

适用：本地/预生产环境的部署、运维、故障处置、备份/恢复、容量保护与
事故响应演练；发布候选的本地门禁检查。

前置条件：Docker 29.x + Compose v5.x；发布镜像
（`docker build -f Dockerfile -t p109-deploy-app:local .`）；0700 secret
目录（`pg_password`、`pg_runtime_password`，0600）；唯一 run ID；
PostgreSQL 16 服务端与匹配 major 的 pg_dump/pg_restore 客户端
（`postgres:16-alpine@sha256:cf78e76683b9ca8c5733cbbdce6c9262b45b6767934dd0a95e671f9a0fc20685`
或同等钉定客户端）。

不适用：生产部署/切换/回滚、云基础设施、HA/DR、生产容量规划、真实
provider 投递保证、安全 clean（见第 25 节与验收报告）。

## 2. 发布 preflight（镜像/二进制/migration/配置/Secret）

1. worktree：`git status --short` 与本轮 targeted `git diff --check`
   干净（历史 findings 保留并单独记录）；
2. 依赖基线：`sha256sum go.mod go.sum` 与基线
   （`50ace433…` / `23cba731…`）一致；
3. migration 清单：22 个 SQL 文件（11 个版本对），checksum 与
   `schema_migration` 一致；
4. 配置校验：`docker compose config -q`（默认 profile）通过；
5. 镜像：`docker build -f Dockerfile -t <tag> .`（非 root、固定基础
   镜像、无 .env/docs/测试文件进入构建上下文，`.dockerignore` 由
   P2-04 审计断言覆盖）；
6. Secret：0700 目录 + 0600 `pg_password`/`pg_runtime_password`；密码
   只经 Docker secret 进入容器 wrapper，组装为进程环境，绝不出现在
   argv/日志/manifest。

## 3. Authority 与依赖关系

| 依赖 | 角色 | authority |
| --- | --- | --- |
| PostgreSQL | 全部业务/协调事实：tenant、binding、identity、session、event、memory、artifact 元数据、audit、queue、execution result、outbox、DLQ、config publication、vector task/rebuild、schema_migration | 唯一事实源 |
| Redis | 限流预算（辅助状态）、（历史）协调缓存 | **不是**任何业务事实源；不可用时 ingress 请求级 fail closed |
| ObjectStore | artifact 字节 | 元数据权威在 PG；对象缺失/不匹配由 reconciliation 降级 |
| OTel Collector | trace/metric 出口 | 出口不可用不改变业务成功/失败分类 |
| Provider | reply 投递 | at-least-once；unknown 不可当 delivered |

## 4. 首次启动顺序

```text
0700 secret 目录 + env 文件（P109_RUN_ID/P109_SECRET_DIR/P109_APP_IMAGE）
  → docker compose up -d --wait postgres redis
  → migrate（trpc-migrate：版本/名称/checksum 校验 + runtime role 供给）
  → docker compose up -d --wait app
  → /healthz 200（readiness）/ /livez 200（liveness）
```

## 5. migration 执行与校验

`trpc-migrate`（退出码 0/2/3/4/5/6/7/8，类别化 stderr）：
fresh init、幂等重放、checksum mismatch exit 4、unknown version exit 6、
missing version exit 5。当前 release 版本 1..11（000011 =
p2_02_restore_trigger_compat）。app 启动 gate 重复同样校验，任何
drift 拒绝启动。

## 6. runtime role、offline recovery role 与权限边界

- `trpc_runtime`：LOGIN、NOSUPERUSER、**NOBYPASSRLS**、非 owner；仅
  USAGE+DML+三个窄 SECURITY DEFINER 函数 EXECUTE；不可读
  `schema_migration`；
- `trpc_claim_owner`：NOLOGIN、BYPASSRLS，仅拥有三个窄函数；
- offline recovery（backup/verify/restore/replay 的租户枚举/数据 COPY）：
  显式高权限操作员路径，运行在隔离目标上，与 runtime 角色严格分离；
  禁止给 `trpc_runtime` 增加 BYPASSRLS/ownership/DDL。

## 7. env 配置与 fail-closed 边界

容量配置（P2-03）：`RATE_LIMIT_REDIS_URL`（空=限流关闭；compose 默认
接入）、`RATE_LIMIT_WINDOW/LIMIT_*`、`INGRESS_MAX_INFLIGHT[_PER_TENANT|
_PER_BINDING]`、`WORKER_CONCURRENCY`、`DISPATCHER_CONCURRENCY`、
`DISPATCHER_CLAIM_BATCH_SIZE`。空值=安全默认；非法/负数/越界/关系破坏
=启动失败。默认关闭项：vector/retrieval/rebuild、object backend
（`BOOTSTRAP_OBJECT_BACKEND=none`）、telemetry export（`TELEMETRY_MODE`
空）、Lark/Telegram binding（显式 opt-in）。

## 8. /livez、/healthz 与 draining

- `/livez`：进程存活即 200（数据库/Redis 故障不影响）；
- `/healthz`：migration ready + 未 draining + worker/dispatcher started
  + PG ping（1s，失败即 Reset）→ 200，否则 503；
- draining（SIGTERM 或 operator）：accepting=false → 新 webhook 503；
  healthz 503；livez 保持 200 至退出。

## 9. Queue/Worker/Completion/Outbox/Dispatcher 的启停

- 启动：runtime Start 顺序 worker.Start → dispatcher hook → dispatcher
  Run；停止：SIGTERM → BeginDraining → worker.Stop（10s 预算）→
  dispatcher.Stop（5s 预算）→ vector 停止 → telemetry flush/shutdown →
  pool/limiter close → 安全退出状态行；
- 有负载时 drain 可能以有界类别（`dispatcher_timeout`/
  `worker_unresolved`）结束；durable 状态保持可回收（Compose 门禁实测）。

## 10. P2-02 backup/verify/restore/replay 调用与安全前置

`trpc-recovery backup|verify|restore|replay`（详见
`docs/P2-02运行文档.md`）：backup 前置 = operator 特权角色 + migration
一致性 fail-closed；restore 前置 = verify 通过 + 目标特权 preflight +
migration gate + 空业务表；restore = 单事务 `--data-only
--exit-on-error --single-transaction`；replay 默认 dry-run 零写入，
repair 仅在隔离目标显式开启。密码只经 0600 PGPASSFILE。

## 11. P2-03 admission/rate-limit/capacity 配置与故障处置

见第 7 节变量表。故障处置：Redis 不可用 → 请求 503（不当作允许）、
readiness 不受影响；capacity_exhausted → 检查 `INGRESS_MAX_INFLIGHT*`
与下游耗时；rate_limited → 检查配额配置与滥用来源（仅能按
scope 类别观察，无业务 ID）。

## 12. PostgreSQL down/restart

检测：healthz 503、`database dependency is unavailable`。动作：恢复
PG → app 池 Reset + fresh ping → queue/Outbox/lease 按既有合同 reclaim。
禁止：在 PG 不可用时伪造 accepted、用增大 pool/无限重试掩盖。

## 13. Redis down/restart

检测：webhook 503 + `rate limit backend unavailable`；Claim/Lease 权威
在 PG，业务事实不受影响。动作：恢复 Redis → 有界探测恢复。禁止：
无限重连、把 Redis 变成事实源。

## 14. ObjectStore missing/mismatch

检测：artifact reconciliation 类别（missing → expired、hash/size/MIME
mismatch → failed）。动作：核对对象存储与 `artifact` 元数据；presign
受 status gate。本轮证据限于本地 MinIO/对象测试边界。

## 15. OTel collector down

检测：export 失败（业务不感知）。动作：恢复 collector；collector
不可用不改变业务成功/失败分类（P1-07 语义，回归覆盖）。

## 16. provider 429/5xx/timeout/unknown

429/5xx → 有限 retry（RetryPolicy MaxAttempts 3）→ DLQ；timeout →
retryable；unknown → 保留可审计状态，永不完成；禁止把 provider 失败
写成业务成功；禁止无限重试。

## 17. 事故响应、升级路径、证据保存和停止条件

事故响应原则：先把系统带到**已知安全状态**（draining → 恢复依赖 →
验证 durable facts → 再恢复流量），每一步保存证据（状态行、exit code、
`SELECT count(*)`、状态行日志），不确定时停止升级。

- 升级路径：操作员自查（本文档矩阵）→ 复现于本地演练 → 修改配置重启
  → 代码缺陷则回到对应阶段边界（P0-09/P2-x）修复并重新走发布门禁；
- 证据保存：`docker compose logs`、`docker inspect`、pg 查询输出、
  `trpc-recovery verify` 输出、release gate 输出；
- 停止条件：durable facts 无法对账（queue/outbox/result 计数矛盾）、
  RLS/role 审计失败、backup checksum 失败、疑似凭据暴露——任一出现
  即停止流量恢复并升级。

## 19. 发布门禁（release gate）

快速门禁：`bash scripts/p204_release_gate.sh`（worktree/依赖基线/
migration 清单/gofmt+vet/compose config/secret scan，6 步，PASS 输出

完整门禁（发布候选必须全部通过，命令与证据见验收报告第 14 节）：

```text

validation → image/build provenance → go test ./... [-race] [-tags=integration]
[-race -tags=integration] → go vet → scanner 状态记录 → RLS/role/catalog
audit → backup/verify/restore/replay smoke → Compose startup/readiness →
bounded failure drill → logs/secrets scan → owner resource snapshot →
rollback/stop decision
```

"发布门禁文档存在且通过"不等于"生产发布已经执行"。

## 23. 配置发布、canary、rollback 和 stale version（P1-08）

- 发布：`tenant_config_version` 插入 draft → validate → publish（触发
  守卫强制 draft 起步，发布路径不可绕过）；rollout 按 percentage 灰度；
- worker/ingress/outbox 消费的 ConfigVersion 与 immutable revision 快照
  绑定：**stale version 被拒**（agent 版本与 tenant config version 不
  匹配即 fail closed）；
- rollback：发布 `rollback` 操作回到既有版本；rollback 后 ingress/
  worker/Outbox 的 config version 与 rollout active_version 一致；
- 新版本不可用 → validate/reject，历史业务事实不被修改；Redis 不是
  configuration fact source；
- 无 admin API：全部经 P1-08 的 PostgreSQL authority 路径。

## 24. 数据库空间、临时目录、连接池和资源泄漏检查

```sql
-- 数据库空间（每个对象与 schema 汇总）
SELECT relname, pg_size_pretty(pg_total_relation_size(oid))
FROM pg_class WHERE relnamespace = 'public'::regnamespace
ORDER BY pg_total_relation_size(oid) DESC LIMIT 10;
-- 连接池
SELECT state, count(*) FROM pg_stat_activity GROUP BY state;
```

- 临时目录：trpc-recovery 的 PGPASSFILE 位于 0700 临时目录、进程退出
  即删；备份目录 0700/文件 0600；宿主 /tmp 为 tmpfs，重启即清；
- 连接池：runtime MaxConns 16（pg_stat_activity 中该 role 的连接数
  不应接近上限）；pool.Reset 由 readiness 在 ping 失败时触发；
- 泄漏检查：goroutine/heap 高水位（soak 测试模式）、admission
  ActiveGlobal 归零、docker stats 内存有界；测试实验室产生的匿名卷
  按创建时间窗口清理（见第 20 节）。

## 25. 日志、metric、trace 查询方式及低基数标签限制

- 日志：结构化 JSON（slog，P1-07）；`docker compose logs app | jq`；
  无-export 模式下无外部日志出口；事件含 component/operation/outcome；
- metric：OTLP → 本地 collector（telemetry profile）→ debug exporter；
  指标族：`trpcagent.http.requests/.duration/.inflight`、
  `trpcagent.queue.operations`、`trpcagent.worker.jobs`、
  `trpcagent.completion.outcomes`、`trpcagent.outbox.dispatches`、
  `trpcagent.channel.outcomes`、`trpcagent.ingress.admission`（P2-03，
  封闭枚举 allowed/rate_limited/capacity_exhausted/backend_unavailable）、
  `trpcagent.telemetry.attributes_dropped`；
- trace：W3C traceparent 由 ingress 注入，经 queue carrier → worker
  attempt links → completion/outbox/sender；collector outage 时 span
  丢弃但不改业务分类；
- **低基数限制**：attribute key 白名单；tenant/session/message/job/
  execution/external_user/destination 等高基数值永远不进入 label；
  超出白名单的值被丢弃并计入 `attributes_dropped`；
- 敏感内容（DSN/password/token/SQL/raw error/prompt）在 logger、
  metric、trace 三层都被合同禁止（安全扫描为证）。
