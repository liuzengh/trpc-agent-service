## 一、数据域与后端映射总表

| 数据域 | 首选后端 | 备选后端 | 复用能力 | 一致性 |
| --- | --- | --- | --- | --- |
| Session（事件/状态） | Redis（热） | MySQL（权威） | `session/redis`、`session/mysql`、`session/inmemory` | 强一致（MySQL）/ 最终一致（Redis） |
| Memory（长期记忆） | Redis（热） | MySQL（落库） | `memory/redis` | 最终一致 |
| Summary（会话摘要） | MySQL（权威） | Redis（缓存） | 平台层 SummaryStore | 强一致 |
| Artifact（产物） | MinIO（文件） | 本地磁盘 | `artifact/*` + `storage/s3` | 强一致（S3） |
| Knowledge（向量） | Milvus | 本地内存/远端向量库 | `storage/milvus`、`knowledge/*` | 最终一致 |
| Audit Log（审计） | MySQL | ES（待确认） | 平台层 AuditStore | 强一致 |
| 配置/元数据 | MySQL | — | 平台层 | 强一致 |

## 二、各后端适合存什么（职责边界）

### 2.1 SQL（MySQL）—— 强一致的「事实源」

**适合存**：所有结构化、需要事务与精确查询的数据。
- 租户、成员、角色（RBAC）
- Agent 与不可变版本（`agent_versions`）
- 工具定义、Agent 工具白名单
- 知识库元数据、文档元数据
- Session 权威落库、事件、摘要
- IM 通道绑定、Outbox、幂等键
- 审计日志、用量记录
- ModelEndpoint、Skill 四级资产

**不适合**：大文件（放对象存储）、高频热数据（放 Redis）、向量相似度检索（放向量库）。

### 2.2 Redis —— 低延迟的「加速与协调层」

**适合存**：
- 消息总线（Streams：inbound/outbound）
- 会话路由表、会话并发串行化锁
- Memory 热缓存（跨节点可见）
- 幂等去重（SETNX）、运行时画像缓存、ModelEndpoint 缓存

**不适合**：需强一致/复杂事务的数据（作权威存储时），大对象。

### 2.3 向量库（Milvus）—— 语义检索的「相似度引擎」

**适合存**：知识库文档的向量嵌入，用于 RAG 语义检索。
- 文档 chunk 向量 + payload（来源、元数据）
- 按 `tenant_id` 分 collection/partition 隔离

**不适合**：结构化业务数据、事务数据、高频读写的会话状态。

### 2.4 对象存储（MinIO，S3 兼容）—— 大文件的「廉价持久层」

**适合存**：Agent 产出的文件（Artifact）、大日志、附件、Skill 资产。
- 路径 `{tenant_id}/{...}` 租户隔离，双向不可读
- 短期签名 URL 下载，不暴露永久 URL

**不适合**：需结构化查询/索引的数据（元数据放 MySQL）。

## 三、统一数据访问抽象与租户级路由

```go
// Router selects backend per (tenant, data-domain). (注释英文)
type Router interface {
    Session(tenantID string) SessionStore
    Memory(tenantID string) MemoryStore
    Summary(tenantID string) SummaryStore
    Artifact(tenantID string) ArtifactStore
    Audit(tenantID string) AuditStore
}
```

- `tenants.data_backend` JSON 逐域指定后端，`storage.Router` 按 `tenant_id` 解析并缓存实现。
- 六数据域默认值：session=redis、memory=redis、summary=mysql、artifact=minio、vector=milvus、audit=mysql。
- 租户 A 可用 Redis session、租户 B 可用 MySQL session，运行时路由，无需改代码替换后端。

## 四、数据同步与迁移策略

| 场景 | 策略 |
| --- | --- |
| Redis → MySQL 迁移 | 双写过渡 + 回填脚本 + 灰度切换，可回滚 |
| 本地向量库 → 远端 Milvus | 文档元数据在 MySQL，向量离线重建 + 双写切换 |
| MinIO 桶迁移 | 元数据在 MySQL，文件跨桶复制 + 签名 URL 重定向 |
| 多节点并发写 session | Redis 会话锁 + 事件单调 seq + MySQL 事务 |
| Memory 跨节点可见 | 写 Redis（原子 Lua）+ 异步落 MySQL，读走 Redis |
| IM 重复投递 | `idem:{msg_key}` SETNX + MySQL 唯一键 |

## 五、一致性取舍

| 后端 | 一致性 | 读写延迟 | 成本 | 运维复杂度 |
| --- | --- | --- | --- | --- |
| MySQL | 强一致 | 中 | 中 | 低 |
| Redis | 最终一致（可调 AOF） | 低 | 中 | 中 |
| Milvus | 最终一致 | 低-中 | 高 | 高 |
| MinIO | 强一致（S3） | 中-高 | 低 | 低 |

**原则**：结构化状态进 MySQL，热数据/队列/锁进 Redis，语义检索进 Milvus，大文件进 MinIO，运行中临时文件在容器 Volume。跨节点共享状态以 MySQL 为权威、Redis 加速。
