# 多后端适配方案

## 数据分工

| 数据类型 | 已提供后端 | 一致性与用途 |
| --- | --- | --- |
| Legacy Session | InMemory、Redis | 开发或共享会话；Redis 使用租户前缀和 TTL。 |
| 可靠会话与运行时 | MySQL | Session、Inbox、Execution、Outbox、审计的事实源。 |
| 会话投影与协调 | Redis | 分布式去重、锁和可重建的 Session 投影。 |
| 知识与 Memory 检索 | Qdrant | 向量检索，MySQL 中的记录为事实状态。 |
| 文档与 Artifact | MinIO / S3 兼容对象存储 | 内容存储，MySQL 保存元数据与权限范围。 |

## 路由方式

Legacy Gateway 通过 `backend_profiles` 为每个租户选择 `memory` 或 `redis` Session 服务；
Redis 键前缀和 TTL 可随租户设置。可靠模式统一以 MySQL 为会话事实源，Redis 只承担协调和
投影，因此不会在同一可靠事务中混用多个会话事实源。

知识库、Memory 和 Artifact 已具备 MySQL + Qdrant + MinIO 组合实现，并以 tenant 范围隔离。
当前向量库和对象存储端点是部署级配置；若需要租户分别选择供应商或实例，应扩展
`backend_profiles` 和服务工厂，不能只增加配置字段。

## 后端迁移

- Redis → MySQL：使用 `-migrate-sessions` 导入会话和事件，支持 dry-run 与重复执行。
- 重建向量索引：使用 `-reindex-kb` 将文档重新进入索引队列。
- 投影重建：Redis 投影丢失时从 MySQL Session 快照重新写入，不影响事实数据。

迁移期间保持单一事实源；完成数据校验后再切换读取路径，避免双写产生无法判定的冲突。
