## 1. 五域路由架构

平台定义五个数据域，每个域独立支持逐租户后端选择：

```
tenant.DataBackend = {
  "session":  "mysql",
  "memory":   "redis",
  "vector":   "milvus",
  "artifact": "minio",
  "audit":    "mysql"
}
```

`storage.Router` 是统一入口，按域解析后端：

| 域 | 路由方法 | 返回类型 | 后端选项 |
|---|---|---|---|
| session | `Router.Sessions(tenantID)` | `*Sessions` | inmemory / redis / mysql |
| memory | `Router.Memories(tenantID)` | `*Memories` | inmemory / redis / mysql |
| vector | `RouterVectorFactory(tenantID)` | `knowledge.VectorStoreFactory` | inmemory / milvus |
| artifact | `RouterArtifactService(tenantID)` | `artifact.Service` | inmemory / minio |
| audit | `RouterAuditRecorder(tenantID)` | `audit.Recorder` | inmemory / mysql |

**Summary 不独立路由**：跟随 Session 后端，由框架 `session/mysql` 自动维护。

### 1.1 支持矩阵：框架能力 vs 平台已接线

要求里点名的后端是“例如 InMemory、Redis、SQL、向量库、对象存储或外部 Memory 服务”。下表区分**框架已提供**与**平台已接线**，避免把“框架有实现”误读成“平台能用”，也说明新增一个后端要动哪一行：

| 域 | 框架提供的后端 | 平台已接线（可选值） | 未接线的接入成本 |
|---|---|---|---|
| session | inmemory / redis / mysql / **postgres** / **sqlite** / **mongodb** | inmemory / redis / mysql | `infra/storage/backends.go` 的 `backendTable` 增加该行的 `session` 构造器（框架 `session/<backend>` 的 `NewService`），并把它加入 `tenant.DataBackend` 白名单；无需改 Router/worker |
| memory | inmemory / redis / mysql / **postgres** / **sqlite** / sqlitevec / mysqlvec / pgvector / chromadb / **mem0** / **tencentdb** | inmemory / redis / mysql | 同上，增加该行的 `memory` 构造器；外部 Memory 服务（mem0/tencentdb）额外需要其自身连接配置 |
| vector（knowledge） | inmemory / milvus / qdrant / pgvector / chromadb / … | inmemory / milvus | `infra/storage/router_domains.go` 的 Router 工厂加一个分支 + 白名单 |
| artifact | inmemory / s3(MinIO) / cos | inmemory / minio | 同上（`RouterArtifactService`） |
| audit / DLQ / outbox / usage | 平台自建（不是框架能力） | mysql + inmemory（audit） | 新增后端需实现 `audit.Recorder`；outbox/DLQ 与 MySQL 事务强绑定，换后端等于换实现 |
| 消息总线 / 锁 / 幂等 / 路由 | 平台自建（Redis Streams + Redis 原语） | redis | 换 MQ 需重写 `infra/bus`（`Bus` 接口已隔离，见 `trpcservice/infra/bus/bus.go`） |

**为什么只接这些**：遵循“**出现第二个实现才纳入 Router**”的准则——每个多出来的后端都要有真实需求、连接池与运维手册支撑，预埋实现只会放大测试与文档面。未接线的后端**不是缺失能力**，而是扩展点：`backendTable` 一行 + 白名单一项即可（`backends_test.go` 会强制两个域同时覆盖，避免只接一个域）。

## 2. 各后端适配说明

### 2.1 Redis

**适配域**：Session、Memory

**实现**：

- 引入 `trpc-agent-go/session/redis` 和 `trpc-agent-go/memory/redis`
- `SessionConfig.RedisURL` / `MemoryConfig.RedisURL` 配置连接
- `Router` 按 `backendID` 缓存实例

**适用场景**：

- 高并发低延迟（~1ms 读写）
- Session 热数据、消息总线、分布式锁
- 跨节点 Memory 实时可见

**一致性**：最终一致（单线程模型，无事务）

### 2.2 SQL（MySQL）

**适配域**：Session、Memory、Audit、DLQ、Outbox、Usage

**实现**：

- Session：`trpc-agent-go/session/mysql`
- Memory：`trpc-agent-go/memory/mysql`（阶段 B1 新增 `go get memory/mysql@v1.11.0`）
- Audit：`infra/audit/mysql.go`（异步批量写入）
- DLQ：`infra/storage/dlqstore/dlqstore.go`（append-only）
- Outbox：`infra/bus/outbox.go`（事务保证）

**适用场景**：

- 强一致要求（ACID 事务）
- 复杂查询（审计日志、用量统计）
- 合规审计（不可篡改）

**一致性**：强一致（事务）

### 2.3 向量库（Milvus）

**适配域**：Vector

**实现**：

- `trpc-agent-go/knowledge/vectorstore/milvus` v1.11.0
- `NewRouterVectorFactory(router, milvusVSF, inmemVSF)` 按租户路由
- Collection 名称按 `kb_id` 自动生成（`sanitizeName` 处理数字前缀）

**适用场景**：

- 知识库语义检索
- BM25 + embedding 混合搜索
- 高维向量相似度计算

**一致性**：最终一致

### 2.4 对象存储（MinIO）

**适配域**：Artifact

**实现**：

- `infra/storage/artifact_minio.go` 实现 `artifact.Service`
- 对象键布局：`{tenant}/{user}/{session}/{filename}/{revision}`
- `NewRouterArtifactService(router, minioSvc, inmemSvc)` 按租户路由
- Bucket 幂等创建

**适用场景**：

- Agent 生成的文件制品
- 知识库原始文档
- 大文件存储（S3 兼容）

**一致性**：强一致（S3 语义）

### 2.5 InMemory

**适配域**：所有五域

**实现**：

- Session/Memory：框架内置 `session/inmemory`、`memory/inmemory`
- Vector：`knowledge.InMemoryVectorStoreFactory()`
- Artifact：框架内置 inmemory 实现
- Audit：`infra/audit/mem.go`（阶段 B 新增，`MemRecorder`）

**适用场景**：

- 开发/测试（零外部依赖）
- 降级选项（Milvus/MinIO 不可用时）
- 单节点演示

**一致性**：强一致（进程内）

## 3. 后端选择矩阵

| 数据域 | 推荐生产后端 | 可选后端 | 备注 |
|---|---|---|---|
| Session | MySQL 或 Redis | inmemory | Redis 适合高并发，MySQL 适合强一致 |
| Memory | MySQL 或 Redis | inmemory | 同上 |
| Vector | Milvus | inmemory | inmemory 仅测试用 |
| Artifact | MinIO | inmemory | inmemory 仅测试用 |
| Audit | MySQL | inmemory | inmemory 为 dev/test 后端 |
| Summary | 随 Session | — | 不独立路由（无 `summary` 键） |
| DLQ | MySQL | — | 仅 MySQL（`dead_letters` 表 + Redis 副本） |
| Outbox | MySQL | — | 仅 MySQL（可靠投递底座，不允许按租户漂移） |
| Usage | MySQL | inmemory（无 MySQL 时） | **不按租户路由**：用量要跨租户汇总做预算判断，落到租户私有内存后端会让预算失真 |

## 4. Router 实现细节

### 4.1 解析逻辑

```go
func (r *Router) backendFor(ctx, tenantID, domain, defaultBackend string) (string, error) {
    t, err := r.tenants.Get(ctx, tenantID)
    if err != nil || t.DataBackend == nil {
        return defaultBackend, nil
    }
    if backend, ok := t.DataBackend[domain]; ok && backend != "" {
        return backend, nil
    }
    return defaultBackend, nil
}
```

### 4.2 实例缓存

- 每个**后端 id** 缓存一个实例（`inmemory` / `redis` / `mysql` 各一个，Router 内 `sessions`/`memories` 两张 map），跨租户共享
- 隔离不靠实例分离，而靠**每次调用传入的 tenantID**：框架侧 `session.Key.AppName` / `memory.UserKey.AppName` 固定为租户 id，Redis 键空间与 MinIO 路径前缀同样带租户
- 后端选择来自 `Tenant.DataBackend[domain]`；未配置则回落平台默认（`sessCfg`/`memCfg.Backend`）

### 4.3 Audit 特殊路由

- `Record(entry)`：按 `Tenant.DataBackend["audit"]` 路由（`inmemory` → 内存实现；否则 MySQL）
- `RecordUsage(entry)`：**始终**走 MySQL（有 MySQL 时），因为用量聚合要跨租户汇总做预算判断，落到租户私有内存后端会让预算失真；无 MySQL 时回落内存实现（dev/test）

## 5. 新增后端接入指南（阶段 44 后的真实步骤）

### 5.1 步骤

1. **添加后端常量**：`storage.Backend*`（如 `BackendPostgres`、`BackendMinIO`）——未接线的后端常量已预置，避免字符串魔法值。
2. **Session / Memory 域**：在 `infra/storage/backends.go` 的 `backendTable` 里给该后端加一行（`session:` 与 `memory:` 两个构造器）。两个域必须同时具备，否则 `backends_test.go` 会失败——这正是把两个 switch 合并成一张表的目的（防止只接一个域）。
3. **Vector / Artifact / Audit 域**：在 `infra/storage/router_domains.go` 对应包装器（`routerVectorFactory` / `routerArtifactService` / `routerAuditRecorder`）里加分支。
4. **配置注入**：在 `SessionConfig` / `MemoryConfig` 等结构体中添加连接参数（`config.Config` 同步加字段）。
5. **main 装配**：构造实例（或让 Router 惰性构造）并注入；如需租户可选，把新后端 id 加入前端租户页的 `data_backend` 可选项。
6. **测试**：`backends_test.go` 的覆盖断言 + 至少一个真容器集成测试（`//go:build integration`）。

### 5.2 示例：接入 PostgreSQL Session（约 15 行）

```go
// 1. 引入框架包
import sessionpg "trpc.group/trpc-go/trpc-agent-go/session/postgres"

// 2. backends.go 的 backendTable 增加一行（memory 同理必须有）
BackendPostgres: {
    session: func(cfg SessionConfig) (session.Service, error) {
        return sessionpg.NewService(sessionpg.WithDSN(cfg.PostgresDSN))
    },
    memory: func(cfg MemoryConfig) (memory.Service, error) {
        return memorypg.NewService(memorypg.WithDSN(cfg.PostgresDSN))
    },
},

// 3. 配置注入
type SessionConfig struct {
    Backend     Backend
    PostgresDSN string // 新增
    MySQLDSN    string
    RedisURL    string
}

// 4. main.go 无需改动：Router 惰性构造该后端，按租户 data_backend 路由
router := storage.NewRouter(tenantMgr, sessCfg, memCfg)
```

> 注意第 4 步"main 无需改动"只对 **Session/Memory** 成立：Router 自己按 `backendTable`
> 惰性构造。Vector/Artifact/Audit 的包装器需要 main 传入两个已构造好的实例
> （例如 `NewRouterArtifactService(router, minioSvc, inmemSvc)`），所以新增这两个域的后端时
> 必须在装配点把它构造出来。
