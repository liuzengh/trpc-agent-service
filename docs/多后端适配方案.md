## 1. 五域路由架构

平台定义五个数据域，每个域独立支持逐租户后端选择：

```
tenant.DataBackend = {
  "session":  "mysql",
  "memory":   "redis",
  "vector":   "milvus",
  "artifact": "minio",
  "audit":    "mysql"
}
```

`storage.Router` 是统一入口，按域解析后端：

| 域 | 路由方法 | 返回类型 | 后端选项 |
|---|---|---|---|
| session | `Router.Sessions(tenantID)` | `*Sessions` | inmemory / redis / mysql |
| memory | `Router.Memories(tenantID)` | `*Memories` | inmemory / redis / mysql |
| vector | `RouterVectorFactory(tenantID)` | `knowledge.VectorStoreFactory` | inmemory / milvus |
| artifact | `RouterArtifactService(tenantID)` | `artifact.Service` | inmemory / minio |
| audit | `RouterAuditRecorder(tenantID)` | `audit.Recorder` | inmemory / mysql |

**Summary 不独立路由**：跟随 Session 后端，由框架 `session/mysql` 自动维护。

## 2. 各后端适配说明

### 2.1 Redis

**适配域**：Session、Memory

**实现**：

- 引入 `trpc-agent-go/session/redis` 和 `trpc-agent-go/memory/redis`
- `SessionConfig.RedisURL` / `MemoryConfig.RedisURL` 配置连接
- `Router` 按 `backendID` 缓存实例

**适用场景**：

- 高并发低延迟（~1ms 读写）
- Session 热数据、消息总线、分布式锁
- 跨节点 Memory 实时可见

**一致性**：最终一致（单线程模型，无事务）

### 2.2 SQL（MySQL）

**适配域**：Session、Memory、Audit、DLQ、Outbox、Usage

**实现**：

- Session：`trpc-agent-go/session/mysql`
- Memory：`trpc-agent-go/memory/mysql`（阶段 B1 新增 `go get memory/mysql@v1.11.0`）
- Audit：`infra/audit/mysql.go`（异步批量写入）
- DLQ：`infra/storage/dlqstore/dlqstore.go`（append-only）
- Outbox：`infra/bus/outbox.go`（事务保证）

**适用场景**：

- 强一致要求（ACID 事务）
- 复杂查询（审计日志、用量统计）
- 合规审计（不可篡改）

**一致性**：强一致（事务）

### 2.3 向量库（Milvus）

**适配域**：Vector

**实现**：

- `trpc-agent-go/knowledge/vectorstore/milvus` v1.11.0
- `NewRouterVectorFactory(router, milvusVSF, inmemVSF)` 按租户路由
- Collection 名称按 `kb_id` 自动生成（`sanitizeName` 处理数字前缀）

**适用场景**：

- 知识库语义检索
- BM25 + embedding 混合搜索
- 高维向量相似度计算

**一致性**：最终一致

### 2.4 对象存储（MinIO）

**适配域**：Artifact

**实现**：

- `infra/storage/artifact_minio.go` 实现 `artifact.Service`
- 对象键布局：`{tenant}/{user}/{session}/{filename}/{revision}`
- `NewRouterArtifactService(router, minioSvc, inmemSvc)` 按租户路由
- Bucket 幂等创建

**适用场景**：

- Agent 生成的文件制品
- 知识库原始文档
- 大文件存储（S3 兼容）

**一致性**：强一致（S3 语义）

### 2.5 InMemory

**适配域**：所有五域

**实现**：

- Session/Memory：框架内置 `session/inmemory`、`memory/inmemory`
- Vector：`knowledge.InMemoryVectorStoreFactory()`
- Artifact：框架内置 inmemory 实现
- Audit：`infra/audit/mem.go`（阶段 B 新增，`MemRecorder`）

**适用场景**：

- 开发/测试（零外部依赖）
- 降级选项（Milvus/MinIO 不可用时）
- 单节点演示

**一致性**：强一致（进程内）

## 3. 后端选择矩阵

| 数据域 | 推荐生产后端 | 可选后端 | 备注 |
|---|---|---|---|
| Session | MySQL 或 Redis | inmemory | Redis 适合高并发，MySQL 适合强一致 |
| Memory | MySQL 或 Redis | inmemory | 同上 |
| Vector | Milvus | inmemory | inmemory 仅测试用 |
| Artifact | MinIO | inmemory | inmemory 仅测试用 |
| Audit | MySQL | inmemory | inmemory 为 dev/test 后端 |
| Summary | 随 Session | — | 不独立路由 |
| DLQ | MySQL | — | 仅 MySQL |
| Outbox | MySQL | — | 仅 MySQL |
| Usage | MySQL | — | `RecordUsage()` 始终路由到 MySQL |

## 4. Router 实现细节

### 4.1 解析逻辑

```go
func (r *Router) backendFor(ctx, tenantID, domain, defaultBackend string) (string, error) {
    t, err := r.tenants.Get(ctx, tenantID)
    if err != nil || t.DataBackend == nil {
        return defaultBackend, nil
    }
    if backend, ok := t.DataBackend[domain]; ok && backend != "" {
        return backend, nil
    }
    return defaultBackend, nil
}
```

### 4.2 实例缓存

- 每个后端类型按 `backendID`（如 `"mysql:default"`、`"redis:tenant-a"`）缓存
- 首次访问时创建，后续共享
- 隔离通过每次调用传入的 `tenantID` 实现（非实例隔离）

### 4.3 Audit 特殊路由

`RecordUsage()` 始终路由到 MySQL（当可用时），不受 `Tenant.DataBackend["audit"]` 影响。原因：全局预算控制需要跨租户聚合。

## 5. 新增后端接入指南

### 5.1 步骤

1. **实现域接口**：
   - Session：实现 `session.Service`（或复用框架）
   - Memory：实现 `memory.Service`（或复用框架）
   - Vector：实现 `knowledge.VectorStoreFactory`
   - Artifact：实现 `artifact.Service`
   - Audit：实现 `audit.Recorder`

2. **添加后端常量**：`storage.Backend*`（如 `BackendMilvus`、`BackendMinIO`）

3. **扩展 Router**：
   - 在 `Router` 或 `router_domains.go` 中添加对应域的 `NewRouter*Factory`
   - 实现 `backendFor()` 解析逻辑

4. **配置注入**：在 `SessionConfig` / `MemoryConfig` 等结构体中添加连接参数

5. **main.go 组装**：在 `main()` 中构建新后端实例，传入 Router

### 5.2 示例：接入 PostgreSQL Session

```go
// 1. 引入框架包
import sessionpg "trpc.group/trpc-go/trpc-agent-go/session/postgres"

// 2. 添加后端常量
const BackendPostgres Backend = "postgres"

// 3. 扩展 Router
func (r *Router) sessionBackend(backend string) (*Sessions, error) {
    switch Backend(backend) {
    case BackendPostgres:
        svc, err := sessionpg.NewService(sessionpg.WithDSN(r.sessCfg.PostgresDSN))
        return &Sessions{svc: svc}, err
    }
}

// 4. 配置注入
type SessionConfig struct {
    PostgresDSN string
}

// 5. main.go 组装
router := storage.NewRouter(tenantMgr, sessCfg, memCfg)
```
