# Agent 与版本

Agent 定义“这个助手要怎样工作”，不负责保存模型服务的 API Key。实际服务与凭据放在运行配置里。

## 页面入口

进入控制台 → 选择租户 → **Agent 工作台**。列表展示当前租户的 Agent；点击新建，填写名称和描述，创建后进入工作台。

## 建立第一个助手

1. 初始化 **Single LLM** 模板。
2. 选中 `assistant` 节点，设置显示名称。
3. 填写 Instruction：说清角色、主要任务、回复语言和需要澄清的条件。
4. 保留 Model Slot 为 `primary`。
5. 在 Requirements 中保留 Models 的 `primary`，能力设为 `chat`。
6. Tool Slots、Knowledge Slots 留空，先不增加组合节点。

可以使用下面这段指令作为起点，再改成你自己的业务说明：

```text
你是我的中文工作助手。
先理解用户的目标，再给出清楚、可操作的回答。
信息不足时，先提出必要的澄清问题。
不要把推测描述为已核实的事实。
```

## 画布和 JSON 如何配合

画布用于选择节点、调整属性和连接结构；JSON 用于查看与编辑完整 AgentSpec。切换前先确认当前输入已写入草稿。显示名称用于帮助人阅读，槽位名称用于资源匹配，两者不要混淆。

当前可编辑结构不等于 Worker 已支持执行所有结构。V1 首次上线使用单 LLM。

## 保存、校验、发布

- **保存**：写入当前草稿。若出现版本冲突，先重新获取服务端草稿，再处理差异，不要反复点击覆盖。
- **校验**：检查已保存草稿是否符合结构要求；先处理报错再继续。
- **发布**：生成 v1、v2 等不可变版本。发布成功后，在版本历史中查看对应内容。

Agent 发布成功，不代表模型凭据已经可用，也不代表运行部署已就绪；这些在 Profile 和 Deployment 阶段继续检查。

## 修改已经上线的助手

在工作台编辑并发布新版本，然后准备新的部署版本。渠道仍指向旧部署，直到你主动修改路由目标。因此，保存指令后机器人没有马上变化，是正常的版本隔离行为。
