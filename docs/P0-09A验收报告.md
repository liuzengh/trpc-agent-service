## 3. Repository Commit 接口和事务边界

`storage.ExecutionResultRepository.CommitExecution` 接收 `ExecutionCommitRecord`，包含 JobID、ExecutionID、TenantID、SessionID、OwnerID、Epoch、FenceToken 和 JSON result。

PostgreSQL Repository 在单个 transaction 中执行：

```sql
INSERT INTO execution_result (...)
SELECT ..., l.owner_id, l.epoch, l.fencing_token, ...
FROM session AS s
JOIN session_lease AS l ON ...
WHERE s.tenant_id = $1
  AND s.session_id = $4
  AND l.owner_id = $5
  AND l.epoch = $6
  AND l.fencing_token = $7
  AND l.leased_until > clock_timestamp()
ON CONFLICT DO NOTHING
```

结果写入和 tenant/session/lease 条件验证位于同一数据库提交边界。`RowsAffected() == 0` 不会被当作成功：Repository 会区分已有相同提交、幂等冲突和当前 fencing/lease 失败。

## 4. Lease / fencing 条件

SQL 重新验证：

- tenant ID；
- session ID；
- owner ID；
- epoch；
- fencing token；
- `leased_until > clock_timestamp()`；
- session 与 `session_lease` 的 tenant-qualified 关联。

旧 owner 在 Validate 之后发生 takeover 时，旧 token 不满足这条 INSERT 的条件；没有成功结果行。Epoch mismatch 返回 `storage.ErrEpochRejected`，过期/缺失 Lease 返回 `storage.ErrLeaseLost`，owner/token mismatch 返回 `storage.ErrFenceRejected`。

`execution.RepositorySink` 只做 R3 commit identity/context 结构校验和 JSON 转换；它不替代 Repository 的数据库 fencing 检查。

## 5. Validate 后 takeover 证据

新增 `TestPostgresExecutionCommitRejectsValidateThenTakeover`：

1. 旧 owner Acquire Lease；
2. 旧 owner 真实调用 `CoordinationStore.Validate`；
3. barrier 暂停旧 owner 继续 Commit；
4. Lease 过期后新 owner 真实 Acquire takeover；
5. 旧 owner 调用 Repository Commit；
6. 旧提交返回 FenceRejected/EpochRejected/LeaseLost，结果读取为 NotFound；
7. 新 owner 使用新 Lease Commit 成功，结果行只记录新 owner。

本测试在最终运行中真实连接 PostgreSQL 并通过；没有将 skip 结果计作证据。

## 6. 新旧 owner 并发证据

新增 `TestPostgresExecutionCommitConcurrentOwnersHaveOneDurableWinner`，在真实 Lease takeover 后并发提交旧/新 owner，并断言：

- 成功提交数为 1；
- 旧 owner 只能得到 FenceRejected/Conflict/EpochRejected/LeaseLost；
- 最终结果 owner、token、JSON result 都属于新 owner。

该测试在最终运行中真实连接 PostgreSQL 并通过。

## 7. 事务回滚、重复提交和错误链

- `TestPostgresExecutionCommitValidAndIdempotent`：有效 token 成功；相同 token、相同 payload 重复提交幂等；相同 Job/Execution 的不同 payload 返回 `storage.ErrConflict`；数据库结果行仍为 1。
- `TestPostgresExecutionCommitRollsBackAfterInsertFailure`：测试 seam 在 INSERT 后、Commit 前返回 `*pgconn.PgError`；断言 `errors.As` 保留数据库错误，读取不到半提交结果，移除 hook 后同一提交可成功。
- `CommitError.Unwrap` 保留 `storage.ErrFenceRejected`、`ErrLeaseLost`、`ErrEpochRejected`、`ErrConflict` 和底层 `*pgconn.PgError`。
- `execution.RepositorySink` 保留 Repository 错误，不修改 Worker 的 `Execute -> Commit -> Ack` 顺序。

上述真实数据库状态断言在最终运行中实际执行并通过；`errors.Is`/`errors.As` 通过 unit 和 PostgreSQL rollback acceptance 双重核对。
