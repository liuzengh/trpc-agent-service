# 工作区整理与源码打包

## 什么保留，什么归档

| 类别 | 处理规则 |
| --- | --- |
| 源码、测试、部署模板、原始需求、验证记录 | 保留在 Git；README 与文档导航作为交付入口 |
| `.env` 和本机账号配置 | 原地保留、权限 0600，不提交、不打包 |
| 日常 PostgreSQL / Redis / MinIO / Qdrant / 监控数据卷 | 原地保留；停止状态或 Docker 标记为 reclaimable 不代表可删除 |
| 历次升级快照、旧二进制、原始 trace、临时排查程序 | 归入私有 `data/archive`，压缩前后校验内容，可恢复 |
| 当前 `bin` 中构建产物 | 可以保留供本机启动；交付源码包不包含它们 |
| 过期覆盖率和已确认失效的 PID | 归档，不沿用为当前测试结果或进程状态 |
| 其他项目或归属不明的 Docker 镜像/卷/缓存 | 本轮不处理，需单独明确所有权和保留策略 |

归档不是完整灾备：本机磁盘损坏仍可能同时丢失数据和归档。归档可能包含有效密钥、原始会话和数据库快照，应与 `.env` 一样保护，禁止分享或上传。

## 本轮整理

2026-09-08 盘点时 `data` 约 1.3 GiB，主要是 16 个历史升级/排查目录和少量快照、trace、日志；`bin` 约 200 MiB。仓库外 Docker 有其他项目和匿名卷，不能根据 reclaimable 数字直接清理。

已归档 24 项、150 个文件：原文件共 1,288,303,748 bytes，压缩包为 554,429,242 bytes，释放约 700 MiB。归档逐文件比较 SHA-256、长度和权限，并再次核对展开文件未变后，才移除展开副本。私有 `.env` 内容校验未变，目录权限收紧为 0700，归档为 0600。

本轮没有启动或停止日常 Agent / 模型 / Tunnel，没有修改 Binding、数据库内容、密钥或 DNS，日常 Docker 容器、卷、镜像和共享 Go 缓存保留。压缩包、逐项恢复清单和校验文件位于 `data/archive/pre-delivery-20260908.3411940635`。当前 `bin` 保留；失效 PID 和旧日志已随归档移走，后续启动会生成新的运行记录。

## 以后清理构建产物

```bash
./clean.sh             # 默认预览，不修改文件
./stop.sh              # 如果 Agent 正在运行，先正常停止
./clean.sh --apply     # 将明确列出的 bin/覆盖率文件移到私有归档
```

`--apply` 使用与启停共享的锁，存在 PID/进程元数据时拒绝整理，失效记录需单独核对。只处理已知构建输出，不删除整个 `bin`，不碰陌生文件、`.env`、源码包、运行数据或 Docker。它不会回收磁盘空间：归档保留原文件，重建可用 `./build.sh`。

不要用 `docker system prune --volumes`、`docker compose down -v` 或递归删除 `data` 来做交付清理。数据库快照不能仅因版本较旧就认定无用；恢复旧数据可能丢失后续业务事实，尤其不能让已发生的工具/IM 操作被重放。

## 如何恢复归档

`clean.sh` 的构建归档保留原始相对路径，Agent 停止且目标文件不存在时，可把需要的文件单独移回；也可以重新构建。

历史快照压缩包应先校验旁边的 SHA-256 清单，再解压到新建的私有临时目录，检查后只恢复需要的文件。**不要直接解压覆盖仓库或数据库，不要自动执行旧目录中的运维程序。**旧 `.env`、PID、二进制和数据库 schema 不能任意混用。

## 如何制作源码交付包

```bash
git status --short     # 确认需要交付的修改均已提交
./package-source.sh
```

脚本拒绝脏工作区和明显的私有/生成路径，只用 `git archive HEAD` 生成源码包及 checksum。相同提交重复打包不会覆盖原包；源码包放在被 Git 忽略的 `dist`，与私有备份分开。它不会复制本机 `.env` 或执行 push。

发布前仍需审阅提交内容。仅靠 `.gitignore` 或路径过滤不能发现写在普通源码/文档中的密钥。
