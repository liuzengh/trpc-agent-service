# 企业微信真实接入与文本收发验收（2026-09-09）

## 本次范围

本次使用真实企业微信智能机器人长连接、当前 Control / Gateway / Worker 与 PostgreSQL、
NATS。模型来自已发布 Deployment 的 Channel Lab `lab-echo` 端点，不是真实大模型。
没有为本次验收修改产品业务代码；部署配置仅给对应 workload 追加 `wecom_preflight`
并重启 Control。运行账户、凭据、Binding、Session 与 Run 为 API 操作产生的业务数据，
不随 Git 提交。本文不包含 Bot Secret、登录凭据、私钥或完整本机部署配置。

## 观察结果

| 项目 | 实际结果 | 证明边界 |
| --- | --- | --- |
| 合成凭据预检 | COMPLETED，WECOM_AUTH_REJECTED | 诊断领取、执行和结果回传有效 |
| 真实 Bot 预检 | COMPLETED / PASS，WECOM_AUTHENTICATED | 本次真实连接认证通过；不是持续在线或消息验收 |
| 私聊文本收发 | 三个标记测试 Run 均 SUCCEEDED；Session 提交和回复发布完成；三条投递 ACCEPTED，每条尝试一次；客户端显示三条回复 | 真实企微与 Worker 回显链路通过 |
| 私聊连续消息 | 同一 Session，sequence 为 1、2、3 | 持久会话关联通过；回显不证明上下文理解 |
| 群内不 @ 对照 | 截至检查未发现对应 Run 或回复 | 有界观察，不推导所有群消息类型 |
| 群内真正 @ 机器人 | 用户通过原生成员提及发送；Run SUCCEEDED、Session 提交和回复发布完成、投递 ACCEPTED、尝试一次；客户端原群显示回复 | 群 @ 文本链路通过 |
| 私聊 / 群聊隔离 | 群消息使用新的 Session，sequence 从 1 开始，与私聊 Session 不同 | 本次同一用户的私聊与一个群分开；不代表多群/多用户矩阵通过 |

真实认证观察时间为北京时间 10:59，私聊为 11:02 附近，群消息为 11:12 附近。
私聊三条中第二条受到自动化中文输入丢字影响，随后发送已核对的英文追问；三条均保留，
不把输入异常包装成正常中文测试。群 @ 最终由用户发送，机器人回复由客户端与持久记录
共同确认，不称为全自动 UI 验收。

## 可复现步骤

1. 准备专用智能机器人 Bot ID / Secret，保存为停用的渠道账户。
2. 应用相应数据库迁移、确认 Control workload 的 `wecom_preflight` 权限和 Gateway runner。
3. 明确同意短时连接可能替换已有客户端后发起预检，核对检查项而非仅看 HTTP 成功。
4. 创建指向已发布 Deployment Revision 的 Binding，先保持路由关闭，再启用接入和路由。
5. 私聊发送唯一测试标记，检查 Run、会话提交、回复发布、渠道投递与客户端显示。
6. 将机器人加入明确的测试群；发送不 @ 对照，再通过成员选择器发送真正 @ 消息。
7. 核对群回复目标和 Session 与私聊不同；消息内容中手写的 @ 字符不替代真实提及。
8. 结束后按需求保留运行，或先暂停路由再停用接入；保留诊断和运行历史。

测试渠道，避免修改共享 Lab 模型端点而影响其他 Bot。
