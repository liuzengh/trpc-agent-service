# 代码实现说明

## 已实现能力

- 多租户控制面：租户、应用、修订、模型、后端、通道、工具和知识库绑定。
- IM 通道：企业微信、微信客服和 WebChat；可靠接收端与 Delivery 支持三类通道。
- 可靠执行：MySQL Inbox、租约、fencing、原子提交、Reply Outbox、投递重试和人工处置。
- 存储：Redis Session、MySQL 运行时、Qdrant 知识与 Memory 索引、MinIO/S3 Artifact。
- 治理：输入与输出 Guardrail、工具白名单、HTTP 工具约束、工具调用账本、单条消息和单次执行调用上限。
- 可观测：OpenTelemetry、tenant 维度请求/延迟/Token/成本指标、JSONL 审计和日志脱敏。
- 运维：Docker Compose、Kubernetes 清单、健康检查、依赖与部署门禁、联调和故障演练脚本。

## 主要入口

| 位置 | 说明 |
| --- | --- |
| `cmd/trpc-service` | 主服务、角色运行、迁移、会话投影查询和运维命令。 |
| `trpcservice/channels` | 通道协议、Gateway、可靠接收端和投递。 |
| `trpcservice/execution` | Worker、领取、提交、阻塞和人工处置。 |
| `trpcservice/controlplane` | 控制面模型与发布修订。 |
| `trpcservice/storage` | Session Router、MySQL、Qdrant 和 MinIO。 |
| `trpcservice/knowledge`、`memory`、`artifact` | 知识、记忆和文件服务。 |
| `migrations` | MySQL DDL。 |

## 当前实现边界

- 灰度发布表已存在，但按会话稳定分流和管理 API 尚未实现。
- 租户级周期预算、危险工具执行前审批尚未进入执行路径。
- 租户级 Session 路由仅支持 memory 与 Redis；向量库和对象存储仍是部署级端点。
- Secret Resolver 支持 `env:` 与 `file:`，尚无 KMS provider；日志脱敏未覆盖所有审计和 trace 输出路径。
- Session 后端不可用时采用摘流量与安全失败，不提供写入补偿队列。

这些边界不影响已提供的最小可靠闭环，但应在生产扩展时优先处理。
