# P0-07 Runtime Completion 完成报告

## 状态

`verified with residual risk`。

本阶段已将 Runtime 成功判定绑定到 tRPC-Agent-Go v1.11.2 的公开 `event.Event.IsRunnerCompletion()`。framework event channel 关闭、adapter pump 退出和 adapter 自有 done channel 不再被当作业务 completion；它们只用于生命周期清理。

## 变更

- `trpcservice/agent/runtime.go`
  - 增加独立的 `frameworkCompletionObserved` 状态。
  - drain 读取并确认 runner completion event 后结束正常消费。
  - 缺失 completion event 时返回 `ErrProducerIncomplete`。
  - 保留 cancellation/deadline、framework error chain 和 bounded pump cleanup。
- `trpcservice/agent/agent_test.go`
  - 正常 drain 夹具改为发送真实 runner completion event。
- `trpcservice/agent/runtime_lifecycle_test.go`
  - 覆盖缺失 completion、completion 提前驱动 drain、completion error 脱敏、重复 completion 和 bounded cleanup。

## 证据

- `go test ./trpcservice/agent/... -count=1`
- `go test ./trpcservice/agent/... -race -count=1`
- `go vet ./trpcservice/agent/...`
- framework source `trpc.group/trpc-go/trpc-agent-go@v1.11.2/event/event.go` 中的公开 `IsRunnerCompletion()` 实现已核对。

## 残余风险

`Runner.Close` 仍只是关闭动作，不是 framework 内部所有 goroutine 的公共 Wait/Done。当前报告证明了公开 event stream 的 completion 和本项目 adapter 的 bounded cleanup，不证明上游 framework 内部全部 goroutine 在每条路径都退出。未来 framework 提供 run-level Wait/Done 合同时再单独补充验证。
