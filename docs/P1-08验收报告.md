## 实现边界

- PostgreSQL 是 revision、rollout、active/baseline、operation idempotency 和历史状态的唯一事实源；没有新增 Redis 配置事实源或进程配置缓存。
- revision 内容在插入后 immutable；状态仅允许 bounded transition；每个 tenant 至多一个 `published` revision。
- publish、canary rollout、rollback 均使用 `ExpectedActiveVersion` CAS；重复 operation id 收敛到已提交结果，复用同一 id 但改变 payload 返回冲突。
- assignment 使用固定 domain separator 和 100 个 deterministic tenant buckets；不读取 prompt、provider response、raw user content 或随机数。
- rollback 只能重新激活曾经发布过的 `superseded`/`recalled` revision；in-flight job 仍可读取历史 runtime-readable revision。
- `AgentJob.Tenant.ConfigVersion`、`AgentRefDTO.Version`、runtime `AgentSpec.Version`、execution commit、`execution_result` 和 reply outbox 使用同一版本；旧 nullable 数据解码为 unknown/zero 并保持兼容。
- vector/retrieval/rebuild、Production Embedder、Production Milvus、P1-09、knowledge source、answer generation 和 `/api/chat` 新语义未实现。
- 真实 Telegram、Lark、Model Provider、Embedding Provider、Production Milvus 请求：`0`。

### 本轮环境激活的测试修正

Docker/Redis fixture 可用后，此前被 skip 的既有测试首次真实执行，暴露三处与 P1-08 migration/语义相关的既有测试假设，已做测试侧修正（production 代码未改动语义）：

2. `completion_integration_test.go`：`TestPostgresAtomicCompletionRejectsConfigVersionMismatch` 期望从 `ErrTenantMismatch` 改为 `ErrConflict`。canonical 分类以 durable fact boundary 为准：reply outbox 与 commit 的 ConfigVersion 互相矛盾属于 request 内部不一致（write conflict）；仅当 commit 与 durable queue payload 版本不一致才是 `ErrTenantMismatch`。PostgreSQL 与 fake 两个 backend 均已实现该分类，旧断言从未在真实 backend 上运行过。
3. 环境发现（非代码改动）：`DATABASE_URL` 非空时服务要求 responder 实现 `RuntimeResponder`，因此 command gate 需要 `MODEL_PROVIDER=runner` 加 dummy provider endpoint；本轮使用的 BOOTSTRAP_*/MODEL_* env 全部为 fail-closed 哑值，渠道 enable 开关默认 false，服务启动与关闭期间对外请求为 `0`。
