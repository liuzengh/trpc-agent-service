## 5. Compose 拓扑与依赖健康

- services：`postgres`（pg_isready healthcheck）、`redis`

  输出、镜像层与 `docker inspect` 均无密码/DSN。

## 6. Migration 与启动 gate

- `migrate` 在 PostgreSQL healthy 后执行；`app` 依赖其成功退出。
- 真实 PostgreSQL 验证：空库初始化到 version 9、幂等重跑、
  checksum mismatch → exit 4、未知未来版本 → exit 6、缺失版本 →
  exit 5、不可达 → exit 3、非法配置 → exit 2；stderr 无 DSN 泄露。
- 部署级 mismatch gate：篡改 `schema_migration.checksum` 后，
  migrate fail closed（日志 `category=checksum_mismatch`），Compose
  拒绝启动 app；恢复 checksum 后应用重新 ready。

## 7. 生命周期与恢复证据（TestComposeLifecycleAndRecovery）

1. 依赖冷启动 + 健康检查通过；
2. migrate 成功（`current_version=9`）后 app 才 ready；
3. 服务进程非 root（/proc/1 Uid）；
4. durable facts：`schema_migration=9`、`job_queue`/`execution_result`/
   `outbox_message`/`tenant`/`agent_app`/`tenant_config_rollout`/
   `tenant_config_operation` 存在；
5. SIGTERM：`stop --timeout 30` 内退出码 0，日志
   `service stopped status=clean`；
6. SIGKILL：退出码 137（docker kill 按设计不触发 restart policy，
   属确定性观察）；操作员 `start` 后重新 ready，durable facts 不变；
7. PostgreSQL outage：`/healthz` 503（fail closed）、`/livez` 保持 200，
   恢复后 `/healthz` 回到 200；
8. migration mismatch fail-closed（见第 6 节）；
9. teardown 后 owner 资源按 label 过滤为 0。

## 10. 环境事实与修复（本轮，均为测试侧或 fixture 侧）

- gate fixture 初次缺少 `trpc_test` 角色（本地 initdb 与 Docker
  `POSTGRES_USER` 行为差异），创建角色后重跑通过；属 fixture 侧修正。
- `TestMigrateCommandAgainstRealPostgreSQL` 原使用自引用 UPDATE 恢复
  checksum（无效语句），改为快照原值+参数化恢复；属测试侧修正。
- compose 共享镜像原先挂在单个测试 cleanup 上被提前删除，改为
  `TestMain` 统一清理；属测试侧修正。
- `docker kill` 不触发 restart policy 为 Docker 既有语义，测试改为
  确定性观察 exit 137 + 操作员重启恢复；`restart: unless-stopped`
  的自动重启语义由 mismatch 重启循环覆盖。
- compose 对一次性 migrate 服务在每次 `up -d app` 时重跑；幂等重跑
  exit 0，篡改场景下 fail closed 并阻断 app 启动（作为 gate 证据记录）。
