## 实现变化

- 平台与 tRPC-Agent-Go 共享同一 tracer provider，补齐之前空 tracer 导致缺失的 invoke_agent/chat/execute_tool span。
- 新增 channel.callback、gateway.accept、queue.publish 和 approval.decide；异步 Worker 继续队列发布 span，Sender 延续执行上下文。
- Migration 011 保存审批申请的 origin_traceparent；新决策通过 span link 关联原申请，不把人工等待算作执行耗时。旧记录保持空值。
- 框架侧丢弃大体积输入输出属性，导出侧采用元数据白名单，并去掉事件正文、错误描述、额外 link/resource 属性；HTTP callback 路径规范化。
- 本地观测栈端口绑定到 loopback；`.env` 的 `TRPC_AGENT_OTEL_ENABLED` 已设为 true，未改动模型凭据、Bot Binding 或 App 发布指针。

这条请求使用真实 Telegram、`glm-5.3-flash`、Redis 和 PostgreSQL。入站、工具允许、工具成功、执行完成和回复成功的审计记录具有相同 trace ID。Tempo 中可见：

```text

→ channel.callback → gateway.accept → queue.publish
```
