## 私有环境

选定的 16 个旧目录和 8 个独立文件共 150 个文件，包含历次升级快照、旧二进制、临时排查工具、旧日志、失效 PID 和过期覆盖率。

原文件共 **1,288,303,748 bytes**，压缩包 **554,429,242 bytes**，释放 **733,874,506 bytes（约 700 MiB）**。逐文件比较 SHA-256、长度和权限，并再次核对展开文件未变化后，才移除展开副本。恢复路径和限制见[环境说明](../workspace-hygiene.md)。

`.env` 内容校验未变；归档根目录为 0700、压缩包为 0600。当前 `bin` 保留，原数据库/对象/向量/监控卷及容器保留，未执行 Docker prune / down / volume 删除。其他项目、匿名卷和共享缓存不在本轮清理范围内。

本轮没有启动或停止日常 Agent、模型或 Tunnel，没有修改 Binding 或恢复旧数据库。失效 PID 和历史日志已经归档，后续正常启动会创建新的运行记录；不应恢复旧 PID 冒充当前状态。

## 清理和打包保护

- `clean.sh` 默认只预览；`--apply` 在生命周期锁下把已知构建产物移入私有归档，不递归删除整个目录。PID、符号链接、已跟踪输出和非普通文件会阻止整理。
- `package-source.sh` 拒绝未提交修改和明显的私有/生成路径，仅导出 Git HEAD，生成版本化源码包及 checksum，不覆盖已有包、不 push。
- `.gitignore` 补充私有 dotenv 变体，保留 `.env.example`；Docker 构建上下文新增排除 `dist` 和 HTML 覆盖率。
- 自动测试覆盖预览不修改、归档可恢复、保留陌生文件/配置、PID/符号链接/跟踪文件拒绝，以及源码包不带私有数据、脏工作区拒绝和校验文件。

## 静态检查整理

本机 Go 1.27.1 / golangci-lint 2.13.2 的完整检查暴露了 229 个检查项，主要来自既有代码，另有新增测试的资源关闭。问题集中在未显式处理的清理/CLI 输出返回值、错误字符串首字母和可简化写法。本轮保留原执行顺序，明确忽略非关键清理返回值，规范错误文案与等价写法；延迟关闭的对象作为参数固定，避免因闭包捕获改变关闭目标。没有关闭检查器或降低检查规则。

修正后 `./scripts/regression.sh` 通过，包含全仓 race、go vet、golangci-lint（0 issues）、构建和文档链接检查。后端集成验证与真实 IM 的通过边界仍见[功能状态](../feature-status.md)，不将这些整理改动称为新的真实业务联调。

随后 `TRPC_AGENT_VERIFY_ISOLATED=1 ./scripts/regression.sh` 同样通过：独立权限测试、两租户/两 Worker 联合测试及恢复套件、PostgreSQL/Redis 备份工具链和告警规则检查均成功，测试仅清理自己创建的容器和合成数据，日常容器保持停止状态。

## 源码包

工作区本地提交后由 `package-source.sh` 导出；包名包含对应 Git commit。接收方按[交付说明](../delivery.md)核对 checksum、构建和启动，不需要本机 `data/archive` 或 `.env`。本轮私有材料不会随源码包交付。
