# Telegram 真实联调验收（2026-09-03）

本记录用于证明 Telegram Bot、平台异步执行链路、真实模型和 Redis Session 已在开发环境完成一次端到端联调。记录不包含 Bot Token、Webhook Secret、消息正文或原始用户/群标识。

## 环境范围

```text
Channel Binding: telegram-tutorial-binding
Tenant/App: tutorial-tenant / tutorial-app
Bot account: trpc_agent_test_bot
公网入口: Cloudflare Quick Tunnel（临时开发地址）
Callback: /callbacks/telegram/telegram-tutorial-callback
Model: glm-5.3-flash（OpenAI-compatible）
Control Plane/Journal: PostgreSQL
Session/Queue/Coordinator/Idempotency/Quota: Redis
```

## 验收结果

真实 Telegram 私聊连续发送三条消息后，数据库汇总结果为：

```text
inbound count: 3
inbound processed: 3
agent run completed: 3
outbound sent: 3
max turn_seq: 3
conversation count: 1
```

Telegram `getWebhookInfo` 同时满足：

```text
callback URL: 已设置为平台 Telegram Callback
pending_update_count: 0
allowed_updates: message, edited_message
```

测试完成后，`TRPC_AGENT_ADMIN_ENABLED` 与 `TRPC_AGENT_POSTGRES_BOOTSTRAP_TUTORIAL` 均已关闭。Channel Binding 保存在 PostgreSQL，服务重启后继续有效。

## 已覆盖链路

```text
Telegram Update
→ Cloudflare HTTPS Tunnel
→ Callback Gateway / Webhook Secret
→ PostgreSQL Inbox / Transactional Outbox
→ Redis Streams
→ Agent Worker / tRPC-Agent-Go Runner
→ 真实模型 / Redis Session
→ PostgreSQL Outbound
→ Telegram sendMessage
→ 用户收到回复
```

## 尚未覆盖

- 固定域名或正式 Cloudflare Tunnel；
- 群聊、Supergroup 和 Topic 的真实联调；
- 图片、文件发送和消息编辑；
- 长时间断网、Telegram 429 和 Webhook 重投演练；
- 生产 Secret Manager 和多副本部署。

Cloudflare Quick Tunnel 地址会随进程重启变化，因此本结果只代表开发环境真实联调，不代表长期生产部署。
