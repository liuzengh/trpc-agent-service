# 故障与业务恢复回归（2026-09-06）

本轮不使用真实模型或 IM，不停止日常 Agent、Redis、PostgreSQL、Tunnel 或监控容器。新增恢复测试不接受业务数据库 URL，自己创建 loopback 临时容器，使用合成数据。

## 验证结果

| 场景 | 验证方法与结果 | 证据边界 |
| --- | --- | --- |
| Worker Context 取消 | 正在处理的任务不 ACK；另一个 Redis Streams consumer 原地 reclaim，同一任务完成并只产生一个 Outbound | miniredis 协议测试，不是生产机器断电 |
| 完成事务失败 | 故障注入发生在完成写入前，重试复用 Runtime 已缓存结果，模型只调用一次 | 内存 Journal 替身验证控制逻辑 |
| 完成成功但确认丢失 | 完成写入后返回错误，再处理同一任务，仍只有一个 Outbound、一次模型调用 | 不宣称任意外部副作用 exactly-once |
| 队列持续不可用 | 连续三次故障之间至少 100ms 退避，可立即取消 | 修复原来报错后立即重试的空转问题 |
| 同 Session / 不同 Session / 重复消息并发 | 既有 Runtime/Coordinator/Idempotency race 测试 | 同 Session 串行，不同 Session 并行；不等于负载容量测试 |
| PostgreSQL 暂时不可访问 | 暂停本次独立容器，300ms 有界入站调用失败；恢复后查不到该失败消息 | 真 PostgreSQL 故障，不操作日常数据库 |
| 全部平台 schema dump/restore | 应用所有迁移、通过真实 Repository 写入业务合成数据，pg_dump 后 pg_restore 到全新数据库，迁移 checksum 校验通过 | 小规模一致快照，不是主从切换、PITR 或 RTO/RPO 达标证明 |
| 恢复后幂等 | 原入站重复仍命中原 request_id/turn_seq；不同正文仍冲突；重复完成只保留一条回复 | PostgreSQL 约束和 Repository 真实执行 |
| 恢复后检查点 | through/floor/version 保留，旧版本 CAS 被拒绝，seen 仍命中 | 没有清空历史、绕过跳过确认 |
| 恢复后发送保护 | sent、unknown、attempting 均不会再次取得发送所有权；换正文仍冲突 | 只验证事实保护，不向 IM 发消息 |

## 可重复命令

```bash
go test -race ./trpcservice/worker ./trpcservice/agent ./trpcservice/coordination ./trpcservice/workqueue
TEST_RECOVERY_DOCKER=1 go test -race -count=1 -v ./trpcservice/recovery
./scripts/e2e-backup-restore.sh
```

新业务恢复测试需要本地已经缓存 `postgres:16-alpine`，旧工具链测试还需要 `redis:7-alpine`；均不自动拉取镜像。清理前核对随机标记与确切容器 ID，只删除自己的临时数据库和 dump。测试数据是可重复生成的，不包含用户消息或密钥；日常卷和此前的私人备份保留。

收尾时增加 `TestIsolatedPostgresContracts`：在另一个独立 PostgreSQL 容器里执行权限、MCP 状态、审批、工具日志、后台任务、控制面及 Session/Memory/Artifact 锁等数据库合约。这样不依赖日常 5432 端口，也避免固定前缀的历史测试碰到业务数据。该套合约已通过；`scripts/regression.sh` 的隔离模式会一并执行。

## 恢复不能保证的部分

SQL 快照只能保留快照时已有的发送和业务事实。若恢复点早于一次真实外部发送或工具操作，就可能失去那次操作的本地记录；**此时禁止直接恢复 Sender/危险工具并盲目重放**。应先停接收与发送，确定数据库、Redis、对象和向量存储的恢复点，核对快照之后的外部操作，再受控恢复。

尚未验证：真实多 Worker/多租户长时间压力、Redis Cluster/Sentinel 切换、WAL PITR、云 S3/远端 Qdrant 恢复、供应商故障与完整业务数据集的 RTO/RPO。运行限制见[容量说明](../capacity.md)。这些上线工作不能用本次合成测试标记为完成。
