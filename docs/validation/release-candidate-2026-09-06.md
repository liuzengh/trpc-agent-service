# 0.2.0-rc.1 收尾候选记录

这是本地开发候选版本，不是生产上线或对外发布声明。既有 Telegram、企业微信 MCP 群文本真实联调证据沿用原记录；新增代码必须经过新版本切换后，才能补记新版真实验证。

## 本轮交付

- 分角色后端装配、SQL/Redis 权限生成器及允许/拒绝集成测试，收窄 Compose/网络模板。
- MCP 单条异常隔离、页级失败保留检查点、受控恢复和原子恢复审计；不扩大原来群/人类账号的授权范围。
- 积压数量/年龄、未知发送、轮询错误与监控快照健康指标，Prometheus 规则和离线规则测试。
- Worker 故障退避、Context 取消接管、完成确认丢失重放；完整平台 schema/合成业务数据的真实 PostgreSQL 备份恢复。
- 统一[运行手册](../operations-runbook.md)、[容量边界](../capacity.md)、[功能状态](../feature-status.md)与[验收映射](../acceptance.md)。
- 安全默认的 `scripts/regression.sh`；`build.sh` 编译全部九个命令，不只编译主服务。

数据库新增迁移为 015/016，主服务源码版本为 `0.2.0-rc.1`。这些更改不修改本地 `.env`，不自动迁移业务库、启用新群、启动服务或加载监控规则；本轮没有 push、创建远端 release 或打 Git tag。

## 回归入口

```bash
TRPC_AGENT_VERIFY_ISOLATED=1 ./scripts/regression.sh
./build.sh
docker compose --profile observability config -q
```

回归脚本清除继承来的测试 DSN/外部端点，不读取 `.env`，先执行全仓库 race、lint 和构建，再运行自己的 Redis ACL 测试容器、PostgreSQL 合约/业务恢复容器、备份工具链和离线 promtool。普通单测中未启用的 S3/Qdrant/真实 IM 测试不能计为本轮已通过。

上述集中回归已通过：全仓库 race/lint/build、独立 Redis ACL、七个包的 PostgreSQL 合约、业务恢复、PostgreSQL/Redis 备份工具链、promtool 规则；九个 CLI 构建和 Compose 配置检查也已通过。文档本地文件链接、回归脚本安全边界和镜像私有配置排除规则加入自动检查。

候选镜像 `trpc-agent-service:0.2.0-rc.1`（本地 ID `0539e7db86bc`）也已构建。单独的 Mock/内存实例在 `--network none`、只读文件系统、无 Linux capabilities、UID 65534 条件下 `/readyz` 就绪，SIGTERM 后退出码为 0；测试容器已清理，不是日常 Agent。构建首次因禁网缺少缓存失败，普通桥接网络又无法访问宿主 loopback 代理；仅构建时使用宿主网络及已有代理变量后成功，没有改变运行时网络或把应用凭据传入构建。

最终检查时，本机日常模型 8787、Agent 8080、PostgreSQL 5432、Redis 6379 均没有监听；本轮没有自动启动这些服务。源码与镜像完成不代表日常数据库已经迁移到 016。

曾尝试复用本机测试 PostgreSQL 端口时，因依赖未运行而无法创建测试 schema；没有把这次失败记为通过。随后新增独立 PostgreSQL 合约测试，所有数据库用例在自己创建的临时实例中运行，包括部分使用固定前缀的历史 Session/Memory 测试，避免误用日常数据库。

1. 在准备测试时，启动本地模型和数据依赖，备份后迁移 015/016，再启动候选版本；确认本地 readiness。
2. 在原已授权企业微信群里发送一条不含敏感信息的图片/文件，再 @机器人发一条有新标记的正常文本。验证媒体隔离、正常文本继续处理、检查点前进和回复不重复。图片不会被理解或下载，预期也不会收到图片分析回复。
3. 新版群文本通过后，按需要复核 Telegram 的新增回执；真实分页、大群和长时间压力另安排受控场景，不用不断重复基础“你好”测试代替。

真实通知接收方仍后置；生产 SSO/Secret Manager、分角色 LOGIN/Redis 凭据、CNI 标签/网络规则、云后端、主从切换/PITR 和 RTO/RPO 需要部署环境。通用 MCP 工具、多种 Agent 编排、管理 UI 和完整多媒体属于额外功能，不把它们写成当前已完成。

## 已知限制

- 异步 Worker 每进程一个消费者，未实现消费者池；没有真实模型高负载容量结论。
- 企业微信 MCP 同人同秒同文可能合并，有限重叠窗口不能覆盖所有晚到消息；未知发送必须核对，不能自动重发。
- Redis Stream 近似 MAXLEN 裁剪不保证保留全部未 ACK 任务；需要按故障窗口配置容量并监控积压。
- SQL 回滚到更早备份会丢失恢复点之后的外部操作事实。先核对副作用，不能恢复数据库后直接无限重放。
- 权限与网络配置通过生成/隔离验证，不代表已应用生产。实际告警通知尚未配置。
