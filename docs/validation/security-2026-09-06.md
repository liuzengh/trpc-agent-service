# 接口与密钥安全改动验证

日期：2026-09-06。此前追踪阶段已提交为 `1222bc4`；本记录对应其后的访问控制改动。

## 本轮覆盖

- `/chat`、`/inbound` 默认 404；启用后使用 Bearer，按租户/Binding Key/User ID 精确授权。
- 在 Runner 或 Inbox 写入前拒绝越权；拒绝使用 HTTP 入站绕过 IM 回调验签。
- EnvStore 默认拒绝，按租户、用途、引用三项匹配；Revision Model 不再直接读取任意环境变量。
- Admin 创建配置和启用 Channel 更新前校验 grant；运行时仍校验；未授权配置不会落库。
- Storage/Embedding/Telegram/WeCom 传递密钥作用域；S3 和 OpenAI Embedding 不再隐式使用机器凭据。
- Gateway/Admin/Relay/Sender 不需要加载模型 Key；Gateway 不挂载 Admin 或 `/chat`。
- Kubernetes 六角色与 migration 使用不同 Secret，入口按角色限制命名空间。这里只测试模板，不代表已部署集群。

## 对当前手动环境的影响

没有停止或重启日常 Agent、workbuddy2api、Redis、PostgreSQL 或 Tunnel，也没有更新 Bot Binding/发布指针。新 binary 已构建，旧进程继续运行；本地 `/readyz` 和公网 `/healthz` 均返回成功。

仅为 `.env` 增加现有 Telegram 的两个精确 grant、显式关闭 HTTP 调试，并将文件权限收紧为仅所有者读写。模型和 IM 密钥的值保持不变。新安全行为在下次正常启动后生效；本轮未要求用户重复手工测试。

未执行多进程数据库/压测脚本（避免与日常队列混用）；它们已补鉴权参数并通过语法检查。真实集群、数据库 GRANT/Redis ACL、在线撤销与外连目标控制仍未完成，边界见[安全说明](../security-boundaries.md)。
