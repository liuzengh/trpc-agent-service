## 原因与修正（0.2.0-rc.2）

对原测试群固定的 19:40–19:42 窗口进行有界只读比较，只输出字段名和相等性：同一图片的 `userid`、`send_time`、`msg_type` 保持相同，`image.media_id` 在两次请求中不同。旧隔离指纹包含这个变化字段，导致重叠读取被当成新记录。

媒体隔离改为 `mcp_reject2_` 的稳定信封分组：租户 + Binding + 群 + 发送者 + 秒级时间 + 消息类型，不纳入媒体访问标识或 URL。缺少稳定源消息 ID 的代价是，同人同秒同类型的不同附件也可能合并；这仅影响不支持媒体的隔离统计，不修改正常文本幂等和发送保护。

新增自动测试覆盖访问标识/URL/姓名变化时分组不变、重复记录只创建一次、发送者/时间/类型/租户/绑定/群的隔离边界以及访问数据不进入隔离记录。使用修正后的解码器再次读取同一真实窗口，两次 `media_id` 仍不同，但新指纹相同、本地隔离 Store 只有一条记录；该诊断没有往业务库补写记录，也没有发消息。临时诊断代码已移除，未保存媒体原始响应。

rc.1 的两条历史隔离记录保留，不通过删行或改表来让验收数量变成 1。rc.2 的真实只读协议验证与自动 Store 测试，不冒充新版收到另一张图片的完整链路实测。
