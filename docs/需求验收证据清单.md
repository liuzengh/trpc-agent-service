## A 组：多租户与节点部署

### A1 租户模型含 tenant_id、应用/模型/工具权限/IM 通道/数据后端配置、审计策略 【✅ 设计定案】
- `domain/tenant/tenant.go:36-43` Tenant 结构含 `DataBackend / Quota / AuditPolicy`
  （治理 + 路由热数据内联）；应用/模型/IM 通道配置是**以 tenant_id 隔离的独立管理域**
  （agent/agent_versions、model_endpoints、channel_bindings，各带 tenant_id 落库）。
- 取舍说明（配置归属边界、何时纳入 Tenant）已文档定案：`docs/租户配置模型与数据后端路由设计.md`。
- 判定：语义完整落地；非「缺失」，属设计取舍并已文档化 → ✅。

### A2 节点部署拓扑：Gateway/Worker/Channel Adapter/Storage Adapter/Admin API/Telemetry Collector 协作 【✅】
- 角色开关 `cmd/trpc-service/main.go`（gateway|worker|admin|all）；Worker `main.go`；
  IM Gateway `channels.NewManager`；Adapter 真实包 `infra/channels/{wecom,feishu}`；
  Admin REST `app/web/*`；Storage Adapter `storage.NewRouter + NewDataStores`；Telemetry `setupTelemetry` OTLP。
- 协作链路：adapter→`PublishInbound`(bus)→worker `ConsumeInbound`→`runner.Run`；
  回复走 MySQL Outbox→`stream:outbound`→gateway `ReadOutbound`→adapter.Send。

### A3 多节点水平扩展 + 消息路由到正确租户/session 【✅】
- `infra/bus/bus.go` inbound stream + `ConsumeInbound`（消费组）；worker 加入 group "workers"、
  consumer 名带 PID（多节点并存）；`RouteKey=route:{tenant}:{session}`（bus.go），
  消息体含 TenantID/SessionID，worker 每消息取上下文（worker.go）。

### A4 无 sticky session、依赖共享 Session/Memory 后端 【✅】
- 无本地会话状态；worker 经 `Router.Sessions(ctx, m.TenantID)` 取共享后端；
  会话跨节点串行由 Redis Lua 会话锁保证（bus.go）。

### A5 租户隔离：配置/数据/工具权限/日志脱敏/密钥管理 【✅】
- 配置隔离：各 MySQL store 查询带 `tenant_id`；数据隔离：session/memory 以
  `AppName=tenantID` 为框架边界，Redis key 带租户前缀。
- 工具权限隔离：`domain/tool` + Registry.IsAllowed + 租户白名单（policy.go）。
- 日志脱敏：`domain/governance` RedactionFilter 经 worker 挂载；
  **新增**统一日志脱敏：`infra/log` 对敏感 attr（password/secret/token/dsn/api_key/…）
  自动打码（log.go redactHandler + `log.Mask`）。
- 密钥管理：`infra/secret` AES-256-GCM，master key env 注入。

### A6 不同租户可选不同数据后端 【✅ 设计定案】
- `infra/storage/router.go`：session/memory 按 `Tenant.DataBackend` 逐租户路由
  （inmemory/mysql/redis）；其余域全局单后端（knowledge=Milvus、artifact=MinIO、
  audit=MySQL）。
- 收敛准则「出现第二实现才纳入 Router」与边界已文档定案：
  `docs/租户配置模型与数据后端路由设计.md` → ✅。

### A7 统一数据访问抽象：Session/Memory/Summary/Artifact/Knowledge/Audit 如何存储 【✅】
- `infra/storage/stores.go` DataStores 聚合（Router/Knowledge/Artifact/Audit）；
  Summary 无独立接口（随框架 session 表，注释明示）。权威说明 `docs/存储与数据访问设计.md`。

### A8 数据同步策略 + 跨后端迁移 【✅ 实现 + 边界如实标注】
- ✅ 同 session 并发一致：Redis Lua 会话锁 + 续期（bus.go）。
- ✅ IM 重复投递幂等：Redis SetNX + outbox idempotency_keys 唯一键 + adapter 去重。
- ✅ memory 写后跨节点可见性：共享 Redis/inmemory 后端（memories.go）；MySQL memory
  后端不存在 → 无「异步落 SQL」分支（按实现收敛，README 未声明）。
- ✅ **跨后端迁移程序（上版 ❌ 已实现）**：`cmd/migrate` CLI（session state+events、
  memory 全量，delete-then-create 幂等；`-auto` 枚举 MySQL 源用户；roundtrip 单测
  `cmd/migrate/migrate_test.go`）。操作手册：`docs/跨后端数据迁移操作手册.md`。
- ⚠️ 已如实标注的边界（非缺口）：框架 v1.11.2 无事件分页公开 API → events 迁移为
  后端「最近事件窗口」；summaries/tracks 无 Service 写入 API → 不迁、目标端重建；
  MySQL 全量补拷 SQL 模板见手册 §5。→ 综合判 ✅（迁移能力落地，边界文档化）。
