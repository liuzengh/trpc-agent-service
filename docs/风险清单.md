## 1. 风险清单

| # | 风险 | 影响 | 缓解措施 | 状态 |
|---|---|---|---|---|
| **R1** | **Admin API 未授权访问** | 管理接口暴露导致租户数据泄露或误操作 | JWT 登录（`POST /auth/login`，bcrypt 口令）+ 外层 auth 中间件（`/healthz`、`/auth/login` 之外的路径一律要 Bearer）+ 路由级权限门禁 + **资源级（按 id）租户归属校验**（越权统一 404，不确认外部资源存在）；角色 = owner（全平台）/admin（单租户）/member（本人租户 + 行级作者规则）。生产另需 `server.production=true` 强制配置签名密钥（缺则拒绝启动） | 已实现 |
| **R2** | **模型超时导致 Worker 阻塞** | 长尾请求（15% ~300s）占用 Worker 槽位，降低吞吐 | 300s 硬超时（`context.WithTimeout`）；模型 HTTP 120s；`consumeWorkers` 信号量限制并发（默认 16）；超时后 context 取消，goroutine 正常退出 | 已实现 |
| **R3** | **IM 消息重复投递** | 同一消息被多次处理，导致重复回复或重复计费 | 四层幂等：①gateway 消息 ID = `channel:platformMsgID`；②adapter 内存 seen 集；③**Redis 两阶段幂等**（租约 90s + 心跳续期，回复落 outbox 后才 `CommitIdem` 24h；失败/崩溃由 `ClearIdem` 或租约到期释放）；④MySQL `idempotency_keys` 唯一键（与 outbox 同事务）。重放时另有**事件级幂等**：以入站消息 id 作 `RunOptions.RequestID`，`resumeRecordedTurn` 从会话事件日志恢复已产出但未落库的回复，不再二次调用模型 | 已实现 |
| **R4** | **Redis 不可用** | 消息总线、锁、幂等、路由、outbound 跟随全部受影响 | 生产建议 Redis Sentinel/Cluster；节点启动**等待 Redis 就绪**（60s 轮询）后再起数据面；运行期每条命令各自重试且总线/派发/投递自愈（`Run` 遇瞬态错误不退出），IM 适配器断线退避重连。**如实说明**：Redis 失联不做粘性 `/healthz` 降级标记（命令会自愈，粘性 503 反而误导），仅告警；MySQL 失联才置 `degraded`（进程内不重连，503 准确） | 部分实现（自愈型降级，无粘性标记） |
| **R5** | **租户数据泄露** | SQL 查询缺少 `tenant_id` 过滤导致跨租户访问 | 所有 Store 层查询强制 `WHERE tenant_id = ?`；集成测试验证隔离（`TestMemoriesMySQLTenantIsolation`）；审计日志按租户分片 | 已实现 |
| **R6** | **密钥明文泄露** | IM token、模型 API key、数据库密码出现在日志或 trace 中 | 统一日志脱敏（正则匹配 password/secret/token/dsn/api_key → `***`）；审计错误类型为粗粒度分类（timeout/run_error）；Secret Manager 使用 AES-256-GCM 加密，master key 从环境变量读取不存储 | 已实现 |
| **R7** | **DLQ 消息积压** | 死信消息未被及时发现和处理 | `platform.dlq_total` OTel 指标告警；Admin API `GET /dlq` 支持按租户过滤；`POST /dlq/{id}/replay` 支持重放；`replayed_at` 防止重复重放 | 已实现 |
| **R8** | **后端迁移数据丢失** | 切换租户后端时旧数据未迁移 | `cmd/migrate` CLI 支持 Session/Memory 跨后端迁移（幂等：delete-then-create）；迁移前可快照配置（`tenant_config_versions`）；向量库可离线重建；对象存储可整体搬迁 | 已实现 |
| **R9** | **RBAC 表未接线**（已消解，保留作历史） | 早期 `roles`/`role_permissions`/`member_roles` 三表既无读者也无写者，易误导 | **阶段 43 已删除这三张表**（`001_tenants.sql` 留注释说明何时补回）；现行权限模型 = 三角色（owner/admin/member）+ 资产行级作者规则，全部由 `app/web/permission.go` 从 `tenant_members.role` + `created_by` 推导，并有 `rbac_matrix_test.go` / `tenant_isolation_test.go` 回归 | 已消解 |
| **R10** | **IM 平台限制** | WeCom 2000 rune / Feishu 4000 rune 截断；流式/卡片形态不完整；图片、文件、撤回等非文本消息当前被忽略 | 出站文本自动截断（`truncateText` 按通道上限）；WeCom 流式占位（先发"正在处理…"再在同一 stream.id 原位替换）；`KindCard`/`KindStream` 已在总线与 gateway 定义并被消费，但**尚无生产者**（卡片/流式回复未启用）；非文本消息**静默丢弃**（未回执、未落审计）——这三项是本轮正在补的实现项，落地后本节同步更新 | 部分实现 |
