# 风险清单

| 风险 | 影响 | 缓解措施 |
| --- | --- | --- |
| IM 重复投递 | 重复执行、重复回复 | Inbox 唯一键、Redis 去重和 Reply Outbox。 |
| 模型超时或限流 | 用户等待、资源堆积 | `context` 超时、错误话术、指标与审计。 |
| 单租户流量洪峰 | 影响其他租户 | 租户并发配额、限流和独立指标。 |
| 会话后端故障 | 无法恢复上下文 | 就绪检查摘流量、MySQL 事实源、Redis 投影可重建。 |
| 多 Worker 并发提交 | 事件乱序、状态覆盖 | 租约、fence、版本校验和协调锁。 |
| 密钥泄露 | 安全事故 | 密钥引用、来源白名单、结构化日志脱敏。 |
| 工具副作用不确定 | 重复扣费或数据损坏 | 工具调用账本、unknown 阻塞、人工处置。 |
| IM 频控与接口变化 | 投递失败 | 通道适配层、Outbox 重试、投递结果审计。 |
| 向量索引失败 | 错误检索或脏数据 | 任务状态机、失败重试、未就绪数据不参与检索。 |
| 成本失控 | 租户成本异常 | Token 与成本指标、单消息模型调用上限。 |

仍需持续完善的控制包括：租户周期预算、危险工具执行前审批、KMS 提供方、跨所有审计和
trace sink 的统一脱敏，以及应用修订灰度发布。
