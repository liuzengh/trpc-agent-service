## 实现边界

- `cmd/trpc-service/main.go` 只保留参数处理、`signal.NotifyContext`/signal cleanup 和最终 `os.Exit`。
- `cmd/trpc-service/lifecycle.go` 提供可测试的 process lifecycle coordinator：显式预绑定 TCP listener、`http.Server.Serve(listener)`、Serve error ownership、startup gate、signal/second-signal gate、process shutdown deadline、剩余时间传递和 safe lifecycle error code。
- `productionRuntime.Stop` 顺序执行 Worker、Dispatcher 和 PostgreSQL pool close，使用 `errors.Join` 保留 Worker/Dispatcher 阶段错误；重复 Stop 通过底层公开 contract 安全返回，pool close 使用一次性 owner。`ForceClose` 只通过 Worker/Dispatcher 的公开 Stop contract 触发取消，并先关闭 pool。
- `trpcservice/web.Server` 增加并发安全的 accepting/draining gate。draining 或 startup 未完成时，webhook 在读取 body、验签、Claim、Enqueue 前返回有限 503；已经通过 gate 进入的 handler 可在 HTTP shutdown deadline 内完成。`/livez` 保持 200，`/healthz` 只返回安全 `status`。
- bootstrap `TenantContext.InternalUser` 最小修复为已验证的外部用户，避免真实 framework Runner 在模型 HTTP 前因空用户失败；未修改 Queue、Worker、Completion、Outbox、Dispatcher 核心算法或 P0-09F 事务顺序。
- production pool 显式保留高于 Worker 并发的连接槽位，并在 readiness Ping 失败时调用 pgxpool `Reset`；这是数据库依赖恢复边界，不是 durable 算法重写。
- G-D 子进程只在显式 `G_D_TEST_MODE=1` 和本地 fake URL 下把真实 channel Sender constructor 的 HTTP transport 路由到 deterministic fake；默认 production path 仍使用真实 Sender constructor，不存在缺配置时自动回退 Fake 的行为。模型 endpoint 也是本地 fake。真实 Lark/Telegram 外部请求次数为 0。

## 停止顺序和 exit code

收到首个 SIGTERM/SIGINT 后，coordinator 执行：

1. 原子设置 server draining/accepting=false，并设置 production readiness draining；`/healthz` 立即 not ready，`/livez` 仍可用。
2. 调用 `http.Server.Shutdown`，使用 process-level bounded deadline 排空已进入的 HTTP handler；deadline 或第二次信号触发 `Close` 强制关闭 listener/连接。
3. 使用 deadline 剩余时间调用公开 `Worker.Stop`，停止 Receive 并按 Worker contract drain 或 recovery unresolved delivery。
4. 调用公开 `Dispatcher.Stop`，停止新 Claim，等待已开始 Sender 到 lock/deadline boundary；Sender 未完成时不执行 durable mutation。
5. 关闭 Queue owner 所需的 PostgreSQL pool。未发送的 pending Outbox 保留在 PostgreSQL，重启后仍可 reclaim；没有承诺退出前发送所有 pending Outbox。
6. 汇总 safe phase/status error；即使前一步失败，后续阶段仍被调用。

exit code 约定：

| 情况 | exit code | 证据 |
| --- | ---: | --- |
| graceful clean shutdown | 0 | coordinator unit contract PASS；Linux real SIGTERM clean subprocess PASS |
| startup、listen、Serve 或 runtime stop failure | 1 | actual binary listen/startup failure PASS；Serve failure unit PASS |
| second signal 或 process shutdown deadline forced close | 2 | bounded forced-close unit PASS |

日志只输出固定 lifecycle status/stage code；不会输出 DSN、SQL、Token、Authorization、AppID、Chat/Receiver ID、Provider body、Prompt、History 或原始 Provider error。

## 验收证据

### Process/in-process

- `TestProcessLifecycleGracefulSignalRunsOrderedCleanup`：PASS。验证 draining -> HTTP shutdown -> runtime cleanup 顺序。
- `TestProcessLifecycleServeFailureStillCleansRuntime`：PASS。Serve unexpected failure 返回非零，并仍执行 HTTP/runtime cleanup；错误原因不会出现在 safe error 文本。
- `TestProcessLifecycleHTTPDeadlineStillStopsRuntime`：PASS。HTTP drain timeout 后仍调用 runtime cleanup，并返回 forced non-zero。
- `TestProcessLifecycleSecondSignalForcesBoundedClose`：PASS。第二次信号不等待完整 graceful deadline，触发 bounded close 和 exit 2 语义。
- `TestSecondSignalGateRequiresTwoSignals`：PASS。首信号只进入 graceful path，第二信号才打开 forced path。
- `TestClassifyRuntimeStopPreservesWorkerAndDispatcherErrors`：PASS。Worker unresolved 与 Dispatcher timeout 不被单一错误覆盖。
- `TestWebhookDrainingGateRejectsBeforeBodyRead`：PASS。gate 关闭时 body read 次数为 0，Ingress call 为 0；`/livez=200`、`/healthz=503`。
- `TestWebhookAlreadyEnteredHandlerMayFinishDuringDrain`：PASS。已进入 body read 的 handler 在 draining 后可以安全完成，不重复进入入口 gate。

### Real OS binary

- `TestGDLifecycleOSProcessStartupAndListenFailures`：PASS。构建并启动实际 `trpc-service` binary；occupied listener 返回非零；invalid startup dependency 返回非零；输出没有 DSN/credential-like value。
- `TestGDSIGKILLReclaimsQueueDelivery`：PASS。实际 binary A 通过真实 PostgreSQL Worker 领取 Job，local fake model 已开始，A 通过 `Process.Kill` 强制终止且不依赖 defer；B 在 PostgreSQL clock 判断 lease 到期后 reclaim。最终为一份 execution result、一份 Queue Ack fact 和一份 reply Outbox；旧 delivery token 的 Ack 被拒绝，stable Job/Execution identity 保持不变。
- `TestGDOutboxLockReclaimAfterSIGKILL`：PASS。实际 binary A Claim 后 local fake Sender 阻塞，A 强制终止；数据库 clock 判断 lock 到期后 B reclaim 并完成 Outbox；旧 owner 在 reclaim 前的 MarkCompleted 被拒绝，未覆盖 B 的 owner/fence。
- `TestGDLifecycleOSProcessSIGTERM`：PASS。Linux test client 启动实际 `trpc-service` binary，并调用 `os.Process.Signal(syscall.SIGTERM)`；child 在配置 shutdown deadline 内以 exit code 0 退出。没有使用 `Kill`、`os.Interrupt`、关闭 stdin 或 HTTP Shutdown 冒充 SIGTERM。

### PostgreSQL outage/restart

- `TestGDPostgreSQLOutageAndRestart` 使用本阶段自己创建且带 owner label 的 `g-d-*` container/network/volume，并在 Linux stable Docker network 中完成 outage、restart、reconnect 和 production recovery。数据库停止期间 `/livez=200`、`/healthz=503`、新 synthetic webhook 不返回 accepted；恢复使用 `pg_isready`、bounded `SELECT 1` 和最终 SQL durable facts 断言。pending Queue Job/Outbox 可继续处理，lease/lock/token fencing 保持有效。
- Windows host-mapped 模式观察到的受控 `unexpected EOF` 仍显式 SKIP；该环境结果没有被全局忽略，也没有用于否定 stable-network Linux evidence。
- 既有 `TestPostgresDispatcherRecoversAfterDockerRestart` 的 `unexpected EOF` 单独保留记录；没有 retry-until-success、固定 sleep 或放宽生产 timeout 掩盖。

### Provider/unknown 语义

G-D 所有 channel Sender transport 为 local deterministic fake，真实 Lark/Telegram send 次数为 0。OutcomeUnknown 仍按现有 Dispatcher/RetryPolicy：不直接 MarkCompleted，稳定 Outbox/dedup/routing identity 保持不变，重启后按 bounded retry policy 处理；外部发送未知仍有 at-least-once 重复风险，不能宣称 provider-side exactly-once。
