# trpc-agent-service 能力与兼容边界

本文描述服务对外提供的运行时角色、Channel 能力、协议范围和明确不支持的行为。角色定义是架构契约；仓库可执行交付边界仍以 Docker Desktop 本地验证为准。未列入支持矩阵的输入必须返回稳定错误或保持 readiness=false，不得静默降级到其他协议。

## 1. 运行时角色

| Role | 权威依赖 | 核心职责 |
|---|---|---|
| `gateway` | PostgreSQL、scoped Secret | HTTP/SSE、OpenAI-compatible 与 A2A façade，创建 durable execution 并读取权威状态 |
| `worker` | PostgreSQL、Redis、ObjectStore、scoped Secret | 消费执行任务、固定 Runtime Profile、调用模型与获批固定 MCP Tool、原子提交 Turn 与回复 Outbox |
| `channel` | PostgreSQL、scoped Secret | Feishu/WeCom callback、可选 WebUI callback、候选验签、身份映射和 durable ingress |
| `channel-delivery` | PostgreSQL、Redis、scoped Secret | 发现历史 binding、消费 Reply Queue、调用 Channel sender、维护 Delivery Ledger |
| `preprocess` | PostgreSQL、ObjectStore、ClamAV、DLP、scoped Secret | 领取 PreprocessJob、下载媒体、扫描、构造 PreparedInput 并派发 |
| `artifact` | PostgreSQL、Redis、ObjectStore、ClamAV、DLP、scoped Secret | 依赖 readiness、upload-intent orphan 回收和 Artifact retention 回收 |
| `audit-relay` | PostgreSQL、独立合规 PostgreSQL | 把业务 Outbox 的审计意图导出为不可变合规事实；跨库写失败不发布源 Outbox |
| `audit-query` | 独立合规 PostgreSQL、PostgreSQL（tenant 状态/version）、scoped Secret | 只读审计查询，强制 tenant scope + 时间范围 + 分页上限，逐查询落二次审计 |
| `audit-purge` | 独立合规 PostgreSQL | 保留销毁 reconciler，只执行 approved 批次、默认 dry-run；破坏性动作不暴露 HTTP 端点 |
| `business-audit-purge` | 业务 PostgreSQL | 业务审计源数据保留 reconciler；仅在 relay watermark 证明已导出后销毁，默认 dry-run；破坏性动作不暴露 HTTP 端点 |
| `webui-local` | PostgreSQL、Redis、Qdrant、DeepSeek Secret | 本地一体化验收组合；自动建立隔离测试控制面、published Skill 与 Knowledge fixture，不作为生产部署入口 |
| `worker-codeexec` Compose profile | PostgreSQL、Redis、ObjectStore、scoped Secret、bubblewrap | 仅承载显式配置的 CodeExec ToolRef；独立 shell-capable 镜像，不替代默认 distroless Worker |

## 2. Channel 支持矩阵

| 能力 | Feishu | WeCom Agent | WebUI |
|---|---|---|---|
| callback transport | HTTP JSON，支持加密事件 | HTTP 加密 XML | HTTP JSON + HMAC |
| challenge | 明文和加密 URL verification | 加密 `echostr` | 不适用 |
| 文本入站 | p2p、group 严格 mention | p2p Agent callback | p2p 风格本地会话 |
| image/file 入站 | p2p 已验证；官方媒体 ID 下载；media-only 群消息忽略 | 官方媒体 ID 下载 | 不支持 |
| 文本出站 | Reply API | Agent message API | mailbox polling |
| 幂等键 | Reply UUID + Delivery Ledger | Delivery Ledger + Provider duplicate check 语义 | ClientRequestID + Delivery Ledger |
| token/client cache | 按 config/secret generation | 按 config/secret generation | 不缓存凭据客户端 |
| 真实 Provider 网络 | 需要显式凭据验证 | 需要显式凭据验证 | 不适用 |

## 3. WeCom 协议边界

WeCom 支持自建应用 Agent 的加密 XML callback、URL 验证、文本/图片/文件入站、媒体下载和应用消息发送。

以下能力不属于 WeCom Agent adapter：

- 智能机器人 WebSocket/Webhook transport。
- `aibot_msg_callback` 与 `aibot_respond_msg`。
- BotID/Secret 长连接订阅、心跳、重连和 connection generation。
- 群聊 `chatid/chattype`、Bot mention 和 Bot 流式回复。
- `response_url` 与 `req_id` 驱动的短期响应协议。

Bot JSON/WebSocket 数据不得回退到 Agent XML parser。若引入 Bot transport，必须作为独立 Adapter 定义连接所有权、binding、Secret scope、ACK、重连、幂等和 ambiguous 对账。

## 4. Feishu 协议边界

Feishu 支持官方事件 callback、签名/加密校验、URL verification、p2p 文本与图片/文件媒体引用、群聊严格 mention 和 Reply API。媒体实际验收范围是 p2p；media-only 群消息不具备可靠的机器人 mention 证据，必须安全忽略，不能作为群聊媒体能力宣称。

群聊消息只有在 mention 范围可确定且正文清洗后非空时进入执行。未知 mention token、无法识别的消息类型或不完整 event envelope 必须 fail closed。

## 5. WebUI 边界

WebUI 复用公共 `channel.Adapter`，不是独立聊天后端。它使用普通 ChannelBinding、opaque route、identity/session key、payload encryption generation、Reply Queue 和 Delivery Ledger。

- 浏览器 token 只保存在页面内存。
- callback 和 mailbox 请求使用 timestamp、nonce 与 HMAC-SHA256。
- mailbox 只保存 provider effect 元数据；回复正文仍存放于加密 ResultStore。
- `TRPC_WEBUI_ENABLED` 默认关闭；生产 `channel` 与 `channel-delivery` 必须同时启用才形成完整链路。
- `webui-local` 使用固定本地默认值，仅适用于隔离开发环境。

## 6. 模型与协议边界

- 模型执行使用版本化 ModelProfile 和 scoped `model_call` Secret；生产客户端使用 DeepSeek OpenAI-compatible endpoint。
- Gateway façade 不拥有本地 Runner；OpenAI-compatible、A2A 和其他协议请求都进入共享 durable execution。
- 输入 payload 的 config version 必须与 ExecutionEnvelope 一致。
- 原始 `media_refs` 不允许进入 Runner；媒体执行只接受包含 ArtifactRef 的 PreparedInput。

## 6.1 MCP Tool 边界

- 仅复用 `trpc-agent-go/tool/mcp` 的 client；service 注册为 tenant-scoped Tool Catalog，Revision ToolRef 固定 `id`、`version` 与 binding digest。
- 端点只允许 HTTPS SSE/streamable；每次发现与调用均校验固定远端名称和审阅 declaration digest。DNS 解析到 loopback、private、link-local、multicast 或未指定地址时拒绝；重定向不跟随。
- Secret 只能经带 `PurposeToolCall` 的 ScopedSecretProvider 注入 `Authorization` 或 `X-API-Key`；结果序列化后超过 256 KiB 拒绝。stdio、动态 URL、动态 ToolSet、`mcpbroker` 与通用 `mcp_call` 不支持。

## 6.2 Sandboxed Code Execution 边界

- 仅复用 `trpc-agent-go/tool/codeexec`、`codeexecutor` 与 `codeexecutor/sandbox` 的公共 API。Worker 默认不注册代码执行工具；必须由 `TRPC_CODE_EXECUTORS` 为固定 tenant/id/version/content digest 显式启用，并指定独立的绝对 `TRPC_CODE_EXECUTOR_WORKSPACE_ROOT`。
- 每次调用忽略模型 JSON 中的 `execution_id`，以已认证的 tenant/request 构造一次性 workspace。Sandbox 使用 managed profile、restricted network 和无宿主环境继承；工作区在调用结束时清理。
- 仅 Python/Bash，且限制代码块数量、源码/输出/磁盘大小、运行时限、CPU、内存及 PID。Sandbox 无法建立或强制隔离时必须失败；禁止回退到 `codeexecutor/local`、宿主 shell、共享 Skill 目录，或把代码产生文件绕过 Artifact 扫描直接返回。
- 执行工具仍是普通 Revision ToolRef：Tool Catalog、PolicySnapshot、参数 Guard、confirmation、执行预算、telemetry 和 audit 均不例外。
- `deploy/compose/Dockerfile` 的 `codeexec` target 以及 Compose `codeexec` profile 是唯一受支持的本地执行入口；它安装 `bubblewrap`、Bash、Python，并用独立 `0700` named volume。生产部署应把该镜像作为单独 Worker pool，不能把这些依赖加入默认 distroless 镜像。

## 7. 存储与后端边界

- PostgreSQL 是 Tenant、Config、Task、Session、Inbox/Outbox、Delivery Ledger 和 Artifact 元数据的权威源。
- Redis 只承载可重放的 Broker、control、wakeup 和 reply transport，不是业务终态权威源。
- ObjectStore 保存 immutable Artifact 内容；PostgreSQL 保存 digest、size、version 和生命周期状态。
- S3-compatible backend 必须支持条件写；启用 Artifact 生命周期时 bucket 必须开启 versioning。
- Scanner 无版本、返回 unknown 或后端不可用时 fail closed。
- InMemory 实现仅用于 contract/unit test，不得作为生产 role 的 fallback。

## 7.1 审计查询与保留销毁边界

- 审计查询只读独立合规库，不提供跨库 JOIN，不暴露业务库 `audit_event`。
- 合规事实默认不可变；销毁是唯一例外，且只能经 `compliance.execute_audit_purge_batch` 受控路径，普通会话 ad-hoc DELETE 被触发器拒绝。
- 破坏性保留操作（approve/execute）不暴露 HTTP 端点，只经 operator CLI/本地管理面执行；`audit-query` 角色只读。
- `compliance.audit_query_record` 不进入普通事件 purge；业务库 `audit_event`/`outbox` 保留在 relay watermark 门禁完成前不做。
- 不支持：按 `latest`/`current` 解析保留策略、跨租户无权限查询、purge 回滚（销毁单向不可逆）。

## 8. Provider 验证边界

协议 fixture 和 mock server 用于验证签名、schema、错误分类和重试语义；真实凭据 smoke 用于验证账号权限、外部网络、Provider API 和可见消息。二者是独立证据，不能互相替代。

真实凭据文件必须是绝对路径、普通文件、非空、至多 64 KiB，且不得授予 group/world 权限。环境变量只携带文件路径和非密钥 locator。

## 9. 兼容性规则

1. 新增字段必须保持旧 `schema_version` 的确定性解码，或显式提升版本。
2. 未知字段、未知 Provider code、未知媒体类型和未知 verdict 默认拒绝。
3. Secret、Config、App Revision、Policy 和 Artifact generation 不允许回退到 current/latest。
4. 已持久化事件始终使用创建时固定的版本；轮换只影响新请求。
5. 不支持能力通过 capability、配置校验或 readiness 明确关闭，不以运行时静默忽略实现。
