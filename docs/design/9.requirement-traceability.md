# 任务书—方案—实现—验收可追溯矩阵

本文是首次交付的评审索引：每一行把任务要求、规范性设计、主要实现落点和验收证据连接起来。设计文档定义约束，代码与测试是可执行证据；没有把 fake demo 的成功外推为真实 IM、云对象存储或生产集群验证。

## 验收入口

| 层级 | 命令 | 证明范围 |
|---|---|---|
| 静态门禁 | `bash scripts/ci/admission.sh` | 格式、依赖边界、Markdown 链接/锚点、build、vet、全部 Go 单测 |
| 无凭据最终路径 | `bash scripts/ci/admission.sh --demo` | 空库单一基线、demo bootstrap、fake model、HTTP 与 SSE |
| 域 e2e | `bash scripts/e2e/backend-adapter.sh {migration,runtime,storage,artifact}`；`bash scripts/e2e/im.sh` | PostgreSQL 16、Redis、MinIO、Qdrant、Vault 与 IM callback 契约；`artifact` 额外验证 PostgreSQL 元数据与共享 MinIO 对象桶的租户隔离 |
| 依赖恢复 | `bash scripts/e2e/dependency-recovery.sh` | PostgreSQL/Redis 短断后的 readiness 与恢复 |
| 真实 IM | [运行手册](../runbook/getting-started.md) 第 3、4 节 | 开发者自有 Feishu/WeCom 凭据和临时 HTTPS tunnel |

## 判读规则

1. “主要代码落点”不是唯一实现文件；它提供评审进入代码的最短路径。
2. 真实 Provider、IM 和外部凭据的验收需要操作者提供自己的账号；无凭据 demo 只证明固定 fake 分支。
3. 当前业务库是首次交付的压缩基线。验收从空 PostgreSQL 16 数据库开始，不支持压缩前开发库的原地升级。
4. 任何新需求必须同时补充本表的任务项、对应设计章节、代码落点和可执行验收证据。
