# 前端功能与 UI 设计

本文件是前端设计建议；产品约束以 [项目规格](../complete-development-plan.md)、[身份 ADR](../adr/0001-enterprise-login-identity.md) 和 [术语表](../../CONTEXT.md) 为准，实现与验证证据统一记录在 [验收文档](../acceptance.md)。

## 用户任务与页面职责

| 页面 | 应承接的功能 | 设计重点 |
| --- | --- | --- |
| 登录与部门上下文 | 固定展示企业微信、飞书、OIDC、Mock 四种能力；只有已配置项可发起登录；登录过期、退出、切换授权部门 | 未配置项弱化并明确标识；Mock 与正式入口视觉分离；未分配部门时解释原因 |
| 用户与部门 | 系统管理员查看企业用户、停用账号、授予系统管理员、创建部门 | 只承接部署级身份和部门目录，不混入当前部门的成员角色编辑 |
| 成员 | 部门管理员维护当前部门成员及角色 | 范围固定为当前部门；不出现企业/平台级角色或组织选择器 |
| 机器人（应用） | 创建应用、业务指令、受管模型选择、工具白名单、存储与预算策略、启停、不可变配置发布、版本查看与回滚 | 列表定位应用，详情阅读配置，编辑集中在表单；发布影响明确 |
| 对话 | 选择活动应用、发送网页消息、等待与增量回复、错误恢复、新会话 | 只承担真实网页对话；外部渠道在对应 IM 客户端真实使用，不在控制台伪造渠道消息 |
| 执行记录 | 消息状态、尝试次数、运行过程、脱敏审计、关联出站结果 | 与对话共用同一份运行文档；区分执行成功与投递成功；超时不能推断已消费，重试次数不能推断已进入 DLQ |
| 会话 | 活动／归档会话、真实聊天记录、来源渠道、会话产出 | Web 对话与管理会话分工明确；外部账号按渠道隔离，不提供手工身份关联；管理员可看外部会话，普通成员只看自己的 Web 会话；归档不删除历史 |
| 平台数据 | 按租户／应用管理知识文档、检索和用户偏好 | 只保留“知识文档 / 用户偏好”两类长期数据；运行产出回到对应会话查看 |
| 系统状态 | 服务版本、依赖健康、运行配置、已有监控入口 | 未加载与健康异常分开；基础设施细节留在运维页面 |

## 功能契约

| 页面 | 交互契约 |
| --- | --- |
| 登录 | 只允许已配置的 Provider 发起登录；Mock 与正式入口视觉分离；登录失败返回可恢复提示。 |
| 机器人 | 权限由逐租户角色决定；发布使用稳定配置版本；模型、工具、存储和渠道只能从受管目录选择。 |
| 对话 | 每次发送生成稳定 `request_id`；网络重试复用同一标识；SSE 按事件游标恢复，切换应用或会话会取消旧订阅。 |
| 执行记录 | 服务端终态、Agent 执行、工具调用与渠道投递分别展示，不用尝试次数推断 DLQ 或投递结果。 |
| 会话 | 基于授权 Session 展示来源、消息和产出；归档保留历史并释放活动会话映射。 |
| 平台数据 | Knowledge 与用户偏好遵守服务端大小、分页和权限约束；运行产出归属于 Session。 |
| 系统状态 | 区分配置状态、依赖健康与运行状态，避免将未加载状态显示为故障。 |

## 视觉与响应式规范

全站共享间距、字号、焦点、状态和按钮样式。导航按实际用户任务划分为对话、机器人、会话、执行记录、模型资产、平台数据和系统状态；新增“会话”不是为了扩张页面数量，而是把管理员的外部渠道会话管理与普通用户自己的 Web 对话彻底分离。

首图以应用管理为样板：页面标题与创建入口、基于实际应用数据的汇总、搜索与状态筛选、应用表格、选中应用的配置阅读区。模型和渠道在列表直接可见。配置详情分为业务指令、模型与工具、渠道绑定，版本历史进入已有版本操作。

桌面保留完整表格；窄屏允许表格容器横向滚动，筛选栏换行，详情区变单列。键盘焦点可见，选择操作使用原生按钮；状态同时提供文字，不只依赖颜色。频繁操作不加出场动画，减少动态效果设置下取消位移动画。

页面通过现有 Console API 读取真实运行数据；设计图中的应用名称与配置仅作为视觉示例，不进入运行数据。
