# P1-05 Tool Policy、Guardrail、Approval、Budget 和统一脱敏验收报告

## 1. P1-05 实际实现范围

本轮基于当前 `agent.ToolInvoker` 入口新增 `trpcservice/tool` 安全边界：immutable server-owned Tool registry、版本化静态 policy contract、fail-closed policy resolver、pre/post Guardrail、bounded process-local budget admission、deferred Approval contract、安全 Audit sink 和统一 `audit.Redactor`。`agent.ToolSpec` 增加 server-owned Tool `Version`/`Capability` metadata；production Runner Factory 注入空 registry 的 fail-closed invoker。

未新增 Tool implementation、Shell、代码执行、任意网络访问、Milvus、Model Provider 接线、migration 或依赖升级。

## 2. 当前 Tool/Runner/Worker/Audit source evidence

`agent.ToolInvoker.Invoke(context.Context, agent.ToolRequest)` 是当前唯一 Tool invocation contract；`ToolRequest` 只携带 TenantContext、immutable AgentSpec、ToolName 和业务 Arguments，`ToolResult` 只有 Content/IsError。模型 tool call 通过 `agent/tool_bridge.go` 进入 `agent/tool.go`。

Runner 在 `agentRuntimeImpl.Run` 中先建立 provider/framework runtime，再由 framework tool bridge 调用 ToolInvoker；异步 Worker 从 Job restore TenantContext，经 Executor 的 deadline、Session lease/fence 和 Agent release 校验后运行。P0-09F completion 仍只处理 execution result、Queue Ack 和 reply Outbox。当前 `trpcservice/tool/tool.go` 原无实现；现有 Audit model、Fake Audit redaction 和 P1-04 Binding Audit 是本轮复用/扩展依据，PostgreSQL 当前没有完整 AuditRepository。

## 3. Tool Policy contract

Policy key 为 tenant、AgentApp、Agent release/config version 和 ToolPolicyRef；decision 同时绑定 server-owned Tool name/version/capability，并要求 bounded expiry。Tool identity/implementation 只能来自 registry；unknown、disabled、undeclared、cross-tenant、wrong Agent/release/config、missing、expired、invalid、stale、version-mismatched、unavailable policy 均 fail closed。caller、用户文本、模型输出和 Tool 参数不能覆盖 tenant、Tool、policy、approval 或 budget owner。

## 4. Guardrail contract

实际顺序为 trusted TenantContext -> registry/policy -> pre-tool Guardrail -> budget reservation -> Tool -> post-tool Guardrail/redaction -> budget commit -> safe Audit。Pre-tool 校验 context、Agent 声明、schema、input bytes、敏感字段/credential、DSN、filesystem traversal 和 shell/code/admin/network capability；post-tool 校验 output bytes、敏感结果和 raw backend error。结果分类包含 allow、deny、approval_required、invalid_input、policy_unavailable、budget_exceeded、redacted、oversized、timeout、cancelled、tool_failure、unknown。

Guardrail failure 不默认 allow；size、context cancellation/deadline、unknown field 和 unknown outcome 均安全拒绝或安全截断。没有完整 DLP/content moderation 声明，也没有无限规则链、retry 或 regex。

## 5. Approval contract 或 deferred 说明

当前源码和权威文档没有 Approval Admin/API、授权管理边界或 durable approval table，因此 Approval 为 `DEFERRED`。本轮只固定未来 contract 类型：server-generated ID、tenant/requester/approver、Tool/capability/resource scope、parameter fingerprint、policy version、status、created/expiry、approved/rejected/revoked time、version/CAS 和 bounded one-time/use count。`approval_required`/`approval_deferred` 一律不执行危险 Tool；没有伪造 approval 或把 caller 提供的 ID 当权限。

## 6. Budget contract 或 deferred 说明

实现了 server-owned TenantContext scope 的 bounded process-local count、duration、concurrency、input bytes、output bytes reservation/commit/release/reclaim。并发 reservation 不超额，reservation TTL 可回收，handle identity 防止 stale owner 释放其他 reservation；cancellation 不永久占用。Token、真实 provider cost、账单、durable reservation/accounting 和 retry/delivery 跨系统幂等为 `DEFERRED`，process-local manager 不是 PostgreSQL durable quota。

## 7. unified redaction contract

扩展现有 `audit.Redactor` 为固定 SHA-256 fingerprint、bounded output、Bearer/Authorization、DSN、常见 secret/token/password/private key、prompt/history/webhook/provider/tool input/output、raw backend error、lease/approval/budget token、object/vector metadata key 分类，并支持注入已知环境 secret value。Audit record 只保存安全 tenant/Agent/session/request/message/Tool IDs、category、version、sizes、latency 和 fingerprint，不保存原始 input/output、prompt、history、provider body 或 token。

这是统一脱敏边界和 deterministic synthetic evidence，不是完整 DLP、content moderation 或所有生产数据分类证明。

## 8. PostgreSQL/Redis durable fact boundary

本轮没有新增 migration：当前源码没有 P1-05 durable policy/approval/budget schema 或完整 production AuditRepository 的统一 contract。PostgreSQL 继续是已实现 metadata、Queue、execution result、Outbox、DLQ 和 Audit 表的事实源；Redis 继续只承担既有 Claim/Lease/epoch/fencing/限流协调。P1-05 process-local budget 不由 Redis 或 PostgreSQL 持久化，也不替代 durable fact。P1-05 不加入 P0-09F 三事实 transaction。

## 9. production composition 和 lifecycle

`newResponder("runner")` 生产路径构造统一 fail-closed invoker：空 Tool registry、FailClosedPolicyResolver、Guardrail/Redactor，无 fake allow、fake approval、fake budget 或 Tool implementation。当前 bootstrap Agent 不声明 Tool，因此现有异步 Worker/Dispatcher/lifecycle 行为不变；未来没有显式 registry/policy/Audit/budget 依赖时危险 Tool 拒绝。P0-09G-D 的 draining、shutdown、recovery 顺序未改。

## 10. tenant/context/policy enforcement

SecureInvoker 再次校验 TenantContext、AgentApp、config version、Agent Tool declaration、Tool version/capability 和 policy expiry。预算 scope 从服务端 TenantContext 生成，caller 不能传入 owner/limit/consumed/token。当前 `/api/chat` 仍为同步 `MemoryStore -> platform.Runner -> EchoResponder` 兼容路径；Lark/Telegram Ingress、Sender、Dispatcher 没有重写。
