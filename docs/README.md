## 关键结论速览

- **租户隔离**：以 `AppName = "t:<tenant_id>/<app_id>"` 作为唯一隔离维度，复用框架既有分键，不引入第二套 ID 体系（§3.2）。
- **无状态 Worker**：不依赖网络级 sticky session，改用共享 Session/Memory 后端 + 会话租约实现软亲和（§3.4）。
- **多后端**：统一数据访问抽象按租户惰性装配 `session.Service` / `memory.Service` / `artifact.Service` / `knowledge.Knowledge`，切后端零 Worker 改动（§4.1、§4.6）。
- **幂等**：IM 会重复投递，所有写路径三层防重（§4.5）。
- **治理**：策略、限额、审批、脱敏、审计全部以 `plugin.Plugin` 注入 Runner（§8.1）。
