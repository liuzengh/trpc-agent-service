# ADR-0009：Console 信息架构按平台权限与租户权限分区

- 状态：**已接受**
- 日期：2026-09-10

## 背景

此前 Console 将“企业用户/部门/知识与偏好/渠道/系统管理”等不同层次资源混在同一导航中，导致 System Admin、Tenant Admin、Tenant Member 的职责边界不清，并让 Channel Binding、External Identity 与 Tenant Membership 产生错误联想。

## 决策

1. **System Admin 区域只管理平台级资源**：`租户 / 用户 / 模型资产 / 数据后端 / 登录设置 / 系统状态`。
2. **Tenant Admin 在当前 Tenant 中看到租户业务管理**：`机器人 / 成员 / 知识库 / 执行记录`，同时保留普通用户的 `对话 / 我的账号 / 我的偏好`。
3. **Tenant Member 只看到自己的工作区与账号能力**：`对话 / 我的账号 / 我的偏好`。
4. **System Admin 不因全局角色自动进入 Tenant 业务页**。若其没有当前 Tenant 的 admin Membership，只能操作系统管理区域。
5. **Channel Binding 主要属于机器人配置**：`机器人 → 渠道`。当前不建立与机器人平级的大型“渠道中心”。
6. **Knowledge 与个人 Memory 分离**：租户共享内容叫“知识库”，个人长期 Memory 叫“我的偏好”，不再使用“知识与偏好”这一混合页面名。
7. **External Identity 不建立用户可见的绑定体系**，只作为 Channel ingress 的消息来源与访问控制事实，也不混入“成员”。平台身份仅由登录体系建立。

## 后果

- 导航直接反映授权边界，减少角色之间的功能误解。
- “系统管理”和“租户管理”可同时出现在一个兼具两类权限的用户界面中，但互不推导权限。
- 机器人渠道接入与平台账号彻底解耦；账号页只呈现平台昵称与登录身份。
