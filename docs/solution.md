# 多租户节点化 Agent 平台方案

本方案基于 tRPC-Agent-Go v1.11.2，面向多个业务部门共享 Agent 平台的场景，覆盖租户隔离、节点部署、共享状态、IM 接入、治理与恢复。以下描述目标架构，当前实现范围见第八节；详细接口、图表和运行步骤见[文档索引](delivery.md)。

## 1. 目标与职责

租户分别创建应用、配置模型与工具权限、绑定 IM 账号并选择数据后端。例如客服使用企业微信和 Redis 会话，研发使用飞书和 SQL 会话；即使外部用户名或群号相同，也不能共享私有数据。

tRPC-Agent-Go 提供 Agent 编排、Runner、Session、Memory、Knowledge、Artifact、Tool/MCP、Plugin/Guardrail、协议服务与遥测能力。平台复用这些接口，新增租户授权、发布路由、后端选择、消息去重、执行协调和回复投递。固定版本没有可直接导入的 OpenClaw Channel 包，平台仅借鉴其职责模型，自行定义适配契约。

## 2. 组件与节点

控制面通过 Admin API 管理 Tenant、App、不可变 Revision、Channel Binding、Backend Profile 和 Policy。租户配置包含模型、工具、通道、后端及审计策略，密钥只保存引用。

数据面由 Channel Adapter 认证并转换外部消息，Gateway 确定租户和会话，Worker 调用 Runner，Storage Router 选择租户后端，Reply Outbox 保存回复与投递结果，Collector 汇集遥测。公共消费者负责受理、去重、执行和发送调度，不解析企微或飞书协议；适配器不直接调用 Runner 或访问任务数据库。新增 Telegram 等通道通过契约和启动注入接入。

生产将 Gateway、Worker、Channel 和后台任务拆为独立部署，共享配置与持久状态，按租户分配资源，按入口或绑定隔离故障。Worker 无需 sticky session，可在任意节点继续会话；当前单条 HTTP/SSE 连接仍由接入节点持有。[架构图](architecture.md#2-系统架构图)给出组件关系。

## 3. 身份与版本

平台从已验证凭据或账号绑定获得租户、应用和主体，拒绝缺失身份，不能让请求正文决定租户。Session 的框架应用名编码为 `t/{tenant}/a/{app}`；SQL 行、Redis 键、向量过滤、对象路径、缓存与审计均保留租户作用域，工具和 Secret 另做授权。

Revision 固定模型、Prompt、工具、策略及后端引用。Runtime 按租户、应用和 Revision 懒加载 Agent/Runner，生产按空闲时间与资源预算淘汰，等待活动引用退出后关闭。首轮会话固定 Revision，灰度和常规回滚只影响新会话。退役前确认没有有效 Pin；紧急禁用先阻断执行，经明确操作换代，不静默改写旧会话版本。[数据模型](data-model.md)定义实体、关系与约束。

## 4. 消息与一致性

企微消息经认证、身份映射后，在 PostgreSQL 一个事务中写入 Inbox 并创建 Run；同绑定、同外部消息重复投递返回原 request_id。提交后才确认受理或发出队列通知。生产 Redis Streams 只负责唤醒，SQL 是任务真相源，持久扫描补发丢失通知。

Worker 按同会话受理序取得运行权，固定 Revision 和后端，将文本转换为 model.Message，再调用 runner.Runner.Run。Runner 读取会话、执行模型和工具、持久化 Event；Worker 作为唯一消费者排空事件并收集回复。Run 终态与 Outbox 原子提交，适配器发送已存正文，明确回执才算投递成功。[核心时序](sequence.md)包含工具与派生数据流程。

同会话使用合作型 Redis 租约，失租取消 Context，异步任务遇忙则持久延后。上游 AppendEvent 无 fencing/CAS，租约不能原子阻止旧节点写入；协调故障拒绝新 Run，不绕过互斥。Event 与 StateDelta 一起提交，Summary 和 Memory 按来源版本派生，旧任务不能覆盖新结果。默认最终一致；强读需等待索引达到目标版本并校验缓存，超时明确失败。

后端按语义分工：SQL 保存配置、任务、审计和持久会话，提供事务但承担连接与写入成本；Redis 提供低延迟热会话和协调，持久性受部署方式影响；向量库保存记忆与知识索引，索引可能延迟；对象存储保存源文件和附件，按版本关联元数据。InMemory 仅用于可接受重启丢失的场景。[存储方案](storage-and-consistency.md)列出服务抽象与能力差异。

迁移先具备按会话目录选择后端的能力，再冻结、排空、复制、校验和切换，下一轮读取新目录而不改变 Revision Pin。知识库迁移冻结文档写入，从固定快照重建索引。回退前确认旧源完整；目标已有新增或删除时先对账，不能直接回退指针。

## 5. IM 通道

企业微信智能机器人通过 Bot ID/Secret 认证长连接，校验消息机器人标识，以 msgid 去重，用 req_id 关联回复；入站推送没有 HTTP 确认。飞书使用 App ID/Secret 与官方长连接，核对应用和企业身份，以 message_id 去重并定位回复，持久受理成功后处理器才确认。

Webhook 扩展由 URL 定位候选凭据，经签名、Token 和应用身份校验后确定绑定。单聊 Session 包含租户、应用、绑定和用户；群聊再加入群、线程及会话世代，按策略共享群上下文或按成员隔离。共享群仍检查实际发言人权限，不暴露个人 Memory；具体编码和验签步骤见[IM 指南](im-channels.md)。

当前仅回复最终文本，企微上限 20480 UTF-8 字节，飞书保守限制 4096 字节。生产流式回复聚合 Event 后限频更新，卡片使用受控模板；媒体由适配器下载、校验并保存受租户保护的引用。撤回关联原消息，不抵消已执行工具。发送按账号和接口配额调度，只在平台允许时有限重试；结果未知不盲目重发，也不重跑 Agent。

## 6. 治理与观测

Plugin 在模型调用前检查权限和预算，Callbacks 检查工具白名单，Guardrail 在内容离开服务前脱敏。需全文判断时缓冲输出。生产策略以共享存储为准，预算按逻辑调用预占并幂等结算，未知费用保留对账。危险工具缺少批准时结束本轮，避免占用租约等待人工；新 Run 校验批准者权限、参数摘要和期限，一次消费批准。

Secret Resolver 先查租户授权，再以工作负载身份取密钥，并限制使用端点。日志、Trace、错误和审计按白名单输出，禁止原始凭据和敏感正文穿透。轮转重建相关 Runtime，但不能追回已外发数据；具体契约见[治理设计](security-and-governance.md#11-生产治理设计)。

生产 traceparent 随持久任务传播，串联 IM、Runner、模型、工具、Session/Memory 与回复，request_id 贯穿幂等和状态关联。指标包括请求量、并发、模型与工具耗时、后端延迟、投递成功率、错误率、token 和租户成本。审计记录租户、通道、用户、会话、Agent、工具、决策、耗时、错误类别、费用及 trace_id；未知值不填零。Collector 使用认证写入、租户授权查询和有界队列，[统计口径](local-deployment.md#生产观测设计)区分重试、未知与实际发送。

## 7. 恢复与部署

节点退出时停止领取任务，取消或等待执行、排空事件，再关闭 Runtime 和存储。未启动任务可恢复；已启动但结果未知不自动重跑。生产只有证明持久结果完整且属于本次执行，才重建回复。模型超时明确失败；工具参数错误可有限修正，权限拒绝不重试，必需工具失败结束执行，可选工具按策略降级，未知副作用转对账。

数据库短暂故障有界重试，不静默降级为内存存储；Memory/Knowledge 故障仅按应用策略降级。生产入口独立就绪检查与局部重启，共享后端故障仍可跨入口传播。

最小部署为一个 Go 进程，默认内存配置与网页；IM 使用 PostgreSQL，凭据从本机私密配置读取。生产采用独立角色、共享高可用后端与 Collector。[部署指南](local-deployment.md)提供启动步骤。容量按实测延迟校准：每节点 100 并发、平均 15 秒一轮，按 60% 水位约 4 RPS；峰值 20 RPS 配五个节点加一个冗余。每轮六个 Event 为 120 写 QPS，每轮 4000 token 为每秒 80000 token；存储与回调需另留突发余量，以上是估算而非压测结果。

## 8. 实现与风险

参考代码已实现多租户配置、发布与 Pin、Runtime/Runner、三类 Session 后端、网页、企微和飞书单聊文本、静态工具权限及三阶段观测。正常收发与本地故障测试分别记录，当前遥测按 request_id 关联，不是完整连续 Trace，详见[实现与验证](acceptance.md)。

Memory、迁移、群聊和媒体、完整治理、多角色部署仍为设计。当前消费者终止会关闭整个进程，租约不提供存储 fencing，未知执行和发送不保证恢复成功。[十三项风险](risks.md)逐项保留触发条件、影响、现有边界、监测、缓解和残余风险。
