# P0-07 阻塞交接结论

**P0-07 已冻结，状态为 `blocked`。**

## 阻塞原因

tRPC-Agent-Go v1.11.2 的 `Runner` / `ManagedRunner` / `Close` 没有公开、合法、稳定的 run completion/wait API。当前只能观察 framework 返回的 event channel，无法证明：

- Runner 内部 event loop 已完成；
- framework producer 已完成；
- `Runner.Close` 返回时 active run 的内部资源已全部结束；
- framework 内部 goroutine 在所有终止路径均已退出。

因此，adapter pump 的 `pumpCompleted` 不能表述为 framework completion，P0-07 不得标记为 `closed`。

## 已完成范围

以下 P0-07 Runtime 能力已完成并通过现有验证：

- request-scoped adapter pump；
- adapter 自有 channel 所有权；
- pump cancellation；
- bounded cleanup；
- producer incomplete 状态；
- pump completion 与 framework channel completion 分离；
- framework Run error 在 drain timeout 路径保留，并可通过 `errors.Is` / `errors.As` 定位；
- 真实 Provider、Runner、Tool 两轮调用和 Platform AssistantCommitter 主链路；
- Provider 和 Agent 配置的多租户隔离；
- adapter 背压满载、取消、deadline、drain timeout、Stop timeout 等 Runtime 行为。

已验证命令：

- `go test ./trpcservice/agent -count=1 -v`
- `go test ./trpcservice/agent -race -count=1 -v`
- `go test ./trpcservice/platform ./cmd/trpc-service -count=1 -v`
- `go test ./trpcservice/platform ./cmd/trpc-service -race -count=1 -v`
- `go test ./... -count=1`
- `go test ./... -race -count=1`
- `go vet ./...`
- `gofmt -l .`
- `git diff --check`
- framework boundary `rg` 扫描

## 剩余事项定级

- framework-level Tool failure/cancellation：后续 framework capability 验证项，不作为当前 Runtime 缺陷。
- Close error + cleanup + framework error 完整注入测试：补充证据项；只有在不改变 Runtime 设计且成本很小时再补充。
- Provider transport 原始 sentinel：补充证据项。
- Tool event metadata 的完整租户/Agent 断言：补充证据项。
- 取消路径不产生成功 audit fact：测试增强项；当前主链路代码已有取消前 commit 检查和独立 bounded audit context。
- 非 `AssistantCommitter` fallback 的逐项写入非原子性：既有限制，不纳入本轮扩大处理。

上述事项即使补齐，也不能解除 framework completion blocker，也不能单独使 P0-07 进入 `closed`。

## 禁止的规避方案

冻结期间不得：

- 把 `pumpCompleted` 改写或描述为 framework completion；
- 通过 goleak 将 framework 内部 completion 认定为 passed；
- 放宽 drain timeout、增加 sleep 或忽略残留 goroutine；
- 访问 framework 私有字段或内部 channel 伪造公共 completion API；
- 扩大到 Gateway、Worker、Job Queue、Repository、真实 IM、鉴权、OTel、向量存储、对象存储或治理；
- 修改 `docs/plan007v1`；
- 回滚其他工作区改动、提交或推送。

## 解除阻塞条件

只有同时满足以下条件，才允许重新评估 P0-07：

1. tRPC-Agent-Go 提供公开、合法、稳定的 run completion/wait API。
2. Runtime 能在 framework run、adapter pump、event drain 和 `Close` 之间建立完整终止协议。
3. framework-level Tool failure/cancellation 具备真实行为测试。
4. Close、Stop、framework error、cleanup error 的组合错误链具备 `errors.Is` / `errors.As` 证据。
5. 能获得 framework 内部 completion 的 bounded goroutine 证据。
6. 重新运行 agent、platform、cmd、全量测试、race、vet、gofmt 和边界扫描并通过。
