## 8. PostgreSQL evidence

- pool 耗尽：MaxConns=1 饱和后 600ms deadline 到即失败（有界），释放/
  Reset 后 SELECT 1 立即恢复；
- durable enqueue 不变量：演练 accepted 数 == job_queue 行数（唯一
  execution id），无重复无丢失；
- claim/reclaim：过期 in_flight 由 definer 回收、旧 delivery Ack 被拒、
  新 owner claim 成功（P2-02 套件回归重跑 + Compose 门禁 restart 后
  attempt 递增）；
- RLS/角色：24 表 ENABLE+FORCE、policy、definer 函数、runtime
  NOBYPASSRLS 探针全部由 P2-01/P2-02 套件在回归中重跑通过；演练中
  runtime 池计数查询被 RLS 隐藏（0 行）本身即为隔离证据。

## 9. Redis evidence

- 三维限流：健康后端允许/配额拒绝分类正确；stop → backend unavailable
  （绝不当作允许或普通限流）；restart → 同 client 有界恢复、窗口计数
  保留；Lua 原子先判后扣合同不变；
- Redis 不是 Queue/Outbox/execution result/config publication/恢复
  manifest 的事实源；Redis stop 时 healthz 保持 200（非 readiness 依赖）
  而 ingress 请求级 fail closed；
- 无限重连不存在：client 有界 timeout，恢复经有界轮询验证。

## 11. observed local capacity / timeout values（仅本地观测，非生产容量结论）

- admission acquire/release 为 O(1) 互斥操作，快速拒绝无阻塞等待；
- 演练（16 并发请求，global=4/tenant=2/chat=4）：accepted 受配额约束、
  其余 429/503 全部分类；admission 高水位 ≤ 配置上限；
- compose 门禁全程 25.6s；rate limit 窗口余量 Retry-After 实测 31s；
- pool 耗尽有界失败 600ms；dispatcher 并发高水位 ≤ 2（配置 2）；
- goroutine/active 计数在停止后有界 settle 内归零。

  运行接线：NOT PROVEN；
