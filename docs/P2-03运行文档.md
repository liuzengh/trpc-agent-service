# P2-03 运行文档：本地有界容量、准入控制与依赖故障保护

本文档描述 P2-03 交付的本地边界：入站 admission 与过载拒绝、
Worker/Dispatcher 有界执行、PostgreSQL/Redis/外部发送依赖故障下的有限
行为，以及本地 Compose 故障演练。它不代表 production capacity planning、
性能基准、autoscaling、Kubernetes/HPA、PostgreSQL HA、Redis Cluster、
跨 Region failover、生产 SLO/RPO/RTO 或 provider 配额认证。

## 1. 当前容量/故障保护基线（源码审查结论）

| # | 项 | 基线状态 |
| --- | --- | --- |
| 1 | HTTP/webhook body 限制 | 既有：`io.LimitReader(body, 1MiB)`（web/server.go，同步与异步路径） |

| 3 | Gateway 顺序 | verify → parse → 服务端 Binding/TenantContext → identity → session → validate → **rate limit → admission（新增）** → resolveAgent → dedup claim → durable enqueue → fast ACK |

## 2. 已有机制与新增机制的边界

- **既有且未改动**：Queue Claim/Ack/Nack/ExtendVisibility、visibility
  recovery、Session Lease、epoch/fencing、原子 completion（result+Ack+
  reply Outbox）、Outbox claim/lock/retry/DLQ、unknown outcome
  reconciliation、P2-01 RLS/角色协议、P2-02 恢复/回放工具、P1-05/07/08
  合同。
- **本轮新增**：`trpcservice/admission`（进程内有界准入闸门）、ingress
  的 rate limit/admission 接线与三类结果、`Retry-After` 头输出、
  `IngressAdmission` 指标、容量相关环境变量（严格 fail-closed 解析）、
  Compose 默认部署的容量接线与容量门禁测试。
- **明确不做**：跨进程 queue-depth cap、租户公平调度、每租户 worker
  预算、每 channel sender 预算、新 migration（000012 未使用）、任何
  Queue/Outbox schema 重写。

## 3. Admission 状态机

```text
请求到达（body ≤1MiB 已由 transport 限制）
  → provider Verify（401）
  → 服务端 Binding/TenantContext 解析（PG registry/definer；401/503）
  → identity upsert/校验（401）
  → tc.Validate（401）
  → [rate limit]：Lua 原子三维判定
       allowed            → 进入 admission
       ErrRateLimited     → 429 + Retry-After（有界）+ reason=rate_limited（不进入 Claim）
       backend unavailable→ 503 dependency_unavailable（不进入 Claim，不当作允许）
  → [admission] Acquire(global → tenant → binding，O(1) 快速拒绝)
       成功               → 持有 slot 直到 fast ACK/失败/panic/cancel 返回路径 defer 释放
       ErrCapacityExhausted→ 429 + Retry-After: 1s + reason=capacity_exhausted（不进入 Claim）
       ErrContextDone     → 503（context 已取消）
  → resolveAgent → dedup Claim → durable enqueue → claims.Complete → 202
```

- 获取顺序全局固定 global → tenant → binding；释放按相反顺序；所有
  路径同序，无死锁；每次获取要么三域全占要么全不占（无部分持有）。
- Acquire 永不阻塞：任一域耗尽即快速拒绝；无无限排队、无无界 channel、
  无 goroutine-per-request 等待。
- 释放幂等（token once），panic-safe（调用方 defer 持有）；enqueue
  失败、draining、context cancel、fast ACK 均恰好释放一次。
- 租户映射条目数受全局上限约束（活跃租户必然持有 ≥1 全局槽），计数归
  零即删除条目；active 计数不可能为负或超过配置上限；high-water 仅供
  容量观测。

## 4. rate_limited 与 capacity_exhausted 的区别

| 项 | rate_limited | capacity_exhausted | dependency_unavailable |
| --- | --- | --- | --- |
| 含义 | 租户/binding/chat 配额耗尽（共享 Redis 预算） | 本进程或明确容量预算耗尽 | PostgreSQL/Redis/必要依赖不可用 |
| HTTP | 429 | 429 | 503 |
| Retry-After | 限流器窗口余量，钳位 [1s, 1h] | 固定 1s（server-owned） | 无 |
| body | `{"error":"webhook request rejected","reason":"rate_limited"}` | `{"error":"webhook request rejected","reason":"capacity_exhausted"}` | 既有 `{"error":"webhook request rejected"}` |
| Claim | 不进入 | 不进入 | 不进入 |
| readiness | 不受影响 | 不受影响 | 保持 fail closed |

## 5. Worker/Dispatcher bounded contract

Worker（既有算法不变，新增并发环境变量）：
- concurrency = `WORKER_CONCURRENCY`（默认 4，1..64，非法即启动失败）；
- VisibilityTimeout(2m) ≥ ingress JobTimeout(2m) 覆盖正常执行预算；
  LeaseTTL(2m) = renew(TTL/3) 的 3 倍余量区分抖动与失权；
- ActionRetry 3 次 / VisibilityRetry 3 次 / ReceiveBackoff 5ms→1s 全部
  有上限；Receive 后端错误走有界 backoff，不 retry-until-success；
- context cancel 后不再启动新 Agent/Tool；Stop/draining 后不再接受新
  delivery；未确认 Ack/Nack 保持 unresolved，不静默转成功；
- 单租户/单 job 无界占用被进程并发上限约束（公平调度 NOT PROVEN）。

Dispatcher（既有算法不变，新增并发/批量环境变量）：
- `DISPATCHER_CONCURRENCY`（默认 1，1..32）、
  `DISPATCHER_CLAIM_BATCH_SIZE`（默认 100，1..上限）、ClaimInterval、
  LockGuard、ShutdownTimeout、RetryPolicy 全部有界并有启动校验；
- ClaimBatch 有界；sender ctx 受 lock guard 与 shutdown deadline 约束；
  429/5xx 走既有有限 retry/DLQ；OutcomeUnknown 永不完成 Outbox；
  停止后 pending Outbox 由新 owner 依既有 lock 过期 reclaim；
- 内存中不复制完整 Outbox backlog（claim batch 有界消费）。

## 6. PostgreSQL/Redis/provider 故障矩阵

| 故障 | 行为 | 证据 |
| --- | --- | --- |
| pool 耗尽 | 有界 acquire（ctx deadline 到即失败），不无界等待；释放/Reset 后立即恢复 | TestPoolExhaustionAcquireIsBounded |
| PG stop | healthz 503、livez 200；durable enqueue 失败不返回 accepted | Compose 门禁 + G-D 证据 |
| PG restart | fresh pool + `SELECT 1`/业务 probe 恢复；queue/Outbox 可 reclaim；事实无重复 | Compose 门禁 + P2-02 套件 |
| Redis stop | rate limit backend unavailable → 503，不当作允许/普通限流；Claim（PG 权威）不受影响 | TestRateLimitBackendFaultClassification + Compose 门禁 |
| Redis restart | 同一 client 有界重连恢复；窗口计数保留 | TestRateLimitBackendFaultClassification |
| Redis timeout/协议错误/cancel | 一律 backend unavailable 分类 | ratelimit 单元/集成 |
| sender 429/5xx/unknown | 既有有限 retry/DLQ；unknown 永不 delivered；retry 有上限 | outbox 既有套件 + 本轮并发/泄漏测试 |
| runner/Tool 超时 | context deadline 传播；非幂等 Tool 不自动重试；失败入稳定类别 | 既有 worker/execution 套件 |

## 7. context、timeout、retry、backoff 与 cancellation

- 所有数据库操作继承 caller context deadline；pool acquire/query/tx/
  commit/rollback 均有界；
- ingress admission Acquire 检查 ctx（已取消即 503）；处理中取消由
  defer 释放 slot；
- Worker/Dispatcher 的 retry/backoff 参数全部有界且有启动校验；
- Redis 客户端 Dial/Read/Write timeout 1s、PoolSize 4；
- 取消后不得有后台 goroutine/Worker/Sender/Tool 继续占用（测试断言
  goroutine/active 归零）。

## 8. 租户隔离与 noisy-neighbor

- admission key 只来自服务端解析的 TenantContext（tenant id 与
  channel-binding id），绝不用 caller 提供的 tenant/binding/channel；
- per-tenant/per-binding 预算保证单租户/单 binding 不能占满全部进程
  容量（tenant A 打满时 tenant B 仍可准入，单元+集成证据）；
- rate limit 三维度共享 Redis 预算，任一维耗尽即拒绝且不回滚其他维
  （Lua 先判后扣，原子）；两租户互不干扰有测试。

## 9. active slot 释放规则

- ReleaseFunc 幂等：重复调用为 no-op；
- defer 持有：正常 202、durable enqueue 失败、draining、context
  cancel、handler panic、fast ACK 后的任何 return 都恰好释放一次；
- fast ACK（202）返回前 slot 不释放；
- 释放不产生负计数、不超过上限（状态机 + 测试断言）。

## 10. unknown outcome 处理

- Outbox sender unknown → 保留 retry/unknown 可审计状态，永不完成；
- completion outcome unknown → 既有 reconciliation 语义不变；
- enqueue/claim 结果 unknown → 不伪造 accepted；
- 不把 unknown outcome 当 success 的断言覆盖在 outbox/ingress 套件中。

## 11. shutdown/draining 行为

- draining gate 拒绝新入口（503）；admission slot 随每个在途请求返回
  而释放；
- Worker/Dispatcher stop 有界（worker 10s、dispatcher 5s shutdown
  预算）；有负载时 drain 可能以有界类别（dispatcher_timeout 等）结束，
  durable 状态保持可回收；
- SIGKILL 后 queue/Outbox lease 过期由新 owner reclaim（既有证据 +
  Compose 门禁重试验证 attempt 递增、行数不丢失不重复）。

## 12. telemetry 与日志脱敏规则

- 新增 `IngressAdmission(outcome)`：outcome ∈ {allowed, rate_limited,
  capacity_exhausted, backend_unavailable, other}（封闭枚举，未知值折
  叠为 other）；
- 禁止进入日志/metric：DSN、password、token、Authorization、SQL、
  SQLSTATE 原文、Redis key、tenant/binding/session/message/job/
  execution/outbox/task/document ID、provider body、prompt/history、
  artifact/vector 内容、raw backend error；
- Retry-After 只输出钳位后的秒数；metric label 无任何无限增长维度。

## 13. Compose 演练步骤

```bash
# 默认 profile 已接入容量配置（RATE_LIMIT_*/INGRESS_*/WORKER_CONCURRENCY/
# DISPATCHER_*，RATE_LIMIT_REDIS_URL=redis://redis:6379/3）。
docker compose config --services          # 1) 默认服务集合不变
docker compose up -d --wait               # 2) app ready（容量配置合法）
# 3) 非法容量配置（如 INGRESS_MAX_INFLIGHT_PER_TENANT>INGRESS_MAX_INFLIGHT）
#    → app 启动 fail closed（startup_failure）
# 4) docker compose stop redis → webhook 503、message_dedup 计数不变（无 Claim）
# 5) docker compose start redis → 有界轮询后 webhook 恢复 202
# 6) docker compose stop postgres → healthz 503、livez 200
# 7) docker compose start postgres → healthz 200、fresh pool 恢复、webhook 202
# 8) 固定 burst（24 请求/并发）→ 结果全部可分类、/proc/1 Threads 有界
# 9) SIGTERM（compose stop -t 25）→ 有界停止状态行；start 后 job_queue
#    行数不变、attempt 递增（pending 可回收）
# 10) docker compose down -v → owner 资源清零
```

门禁测试：`TestComposeCapacityProtectionGate`（cmd/trpc-service，integration
tag），使用 override 启用确定性 Telegram 入口（`env://P203_GATE_SECRET`
占位 secret）+ chat 配额 3 + 默认回环 runner endpoint（执行必然本地失败
→ 无 reply outbox → 零外部请求）。

## 14. 资源清理步骤

- 测试实验室/套件容器与网络：按唯一 run 名删除（`docker rm -f`、
  `docker network rm`），禁止 prune；
- Compose 栈：`docker compose down -v --timeout 25`（teardown 注册为
  t.Cleanup，并核对 label=run_id 资源为空）；
- PGPASSFILE/secret 临时目录：工具退出即删；/tmp 脚本与日志人工删除；
- 无论 PASS/FAIL/timeout/cancel，最终核对 containers/networks/volumes/
  images/temp files/processes/pending cleanup 计数。

## 15. 未证明边界（NOT PROVEN / NOT IMPLEMENTED）

- `Cross-process global queue-depth guarantee: NOT PROVEN`（未实现跨进程
  backlog cap；未使用裸 COUNT 再 INSERT）；
- `Global tenant fairness: NOT PROVEN`（Queue 全局 claim 语义未改）；
- `Production capacity limit: NOT PROVEN`；
- per-tenant worker 执行预算、per-channel sender 预算：NOT PROVEN；
- circuit breaker 接入运行路径：NOT PROVEN（类型存在，未接线）；
- production capacity/autoscaling/HA/SLO 等见验收报告关闭语句。
