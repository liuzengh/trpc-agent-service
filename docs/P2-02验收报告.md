# P2-02 验收报告：本地 PostgreSQL 逻辑备份/恢复与有界会话事件回放

## 1. 状态

`P2-02: verified only as a local PostgreSQL logical backup/restore and
bounded session-event replay/recovery-drill boundary`

## 2. 范围与最小映射

权威计划对 P2-02 的聚合描述（备份恢复和事件回放）本轮固定为两个相互区
分的子边界，全部证据都在本地隔离环境取得：

- **A. PostgreSQL logical backup/restore**：`cmd/trpc-recovery` 离线
  operator 工具（`backup`/`verify`/`restore`/`replay` 四个子命令，
  稳定退出码 0/2/3/4/5/6/7/8/9，category-only stderr，非敏感 JSON
  stdout）；custom/data-only archive；`schema_migration` 数据不写入
  archive，schema 与 role/policy/function 由当前 release migrations
  （1..11）恢复，archive 永远不是可执行 schema 的替代来源。
- **B. Session event replay**：只读既有 `session_event`；默认 dry-run
  （零写入、确定性 SHA-256 摘要、数据库零变化）；唯一允许的可选修复是
  在事件从 1 连续、全部合法且数据库 watermark 偏低时，把同一 session 的
  `last_event_seq` 用 CAS 单调提升到已验证连续 max sequence；不重跑
  Agent/Tool/Sender、不重发 Outbox、不创建 Job/Execution/Memory/
  Artifact、不调用 Provider、不推导或修改 state/state_version/
  summary_version/config version/execution result/外部投递状态。

## 6. 事实源矩阵与 `session_event` 的边界

- PostgreSQL 业务/协调/发布/vector task+rebuild 事实（24 张 tenant 表）
  是本轮 archive 的全部内容；`schema_migration` 数据不进 archive，
  manifest 记录 11 个 migration 的 version/name/checksum 与整体 digest。
- Redis 临时协调状态不进备份；演练用全新空 Redis 证明恢复后的
  PostgreSQL authority（DBSIZE=0 下 reclaim/Dispatcher 全部成立）。
- Milvus 是可重建派生索引，不进备份；恢复目标上 Memory、
  vector_projection_task、vector_rebuild_run 事实完整，P1-06E
  rebuild/reconciliation 仍可显式触发（本轮未运行 Production Milvus，
  也不声称）。
- Object Storage bytes 不在 archive；`artifact` metadata 恢复后，未单独
  恢复对象时由现有 reconciliation 安全识别为 missing/failed/expired；
  本轮不声称 Artifact 内容已恢复。
- SecretRef 恢复；secret 明文不由数据库备份提供，恢复目标需要独立
  secret supply。
- `session_event` 实际记录 8 类事件（user.received / agent.started /
  tool.started / tool.completed / tool.failed / assistant.completed /
  execution.failed / execution.canceled）的 sequence/attempt/parent/
  payload；**没有**记录 tenant、binding、job、execution、outbox、
  configpub、Memory、Artifact bytes 或外部发送结果的完整事实，因此
  本轮明确：不能据此重建上述任何事实，未虚构事件、未重写 P0-09F 
  事务、未把事实表降级成 projection。

## 7. archive/manifest 合同与快照语义

- 备份目录：新建、0700、非 symlink；`archive.pgdump`（0600）、
  `manifest.json`（0600）、`COMPLETED`（0600）；先写同目录临时文件，
  fsync、checksum、manifest 完成后再原子发布 COMPLETED；中断或失败的
  备份永远不被 verify/restore 接受。
- 一致快照：owner 连接 `BEGIN ISOLATION LEVEL REPEATABLE READ` +
  `pg_export_snapshot()`；每表行数与 `pg_dump --snapshot=<id>
  --data-only` 来自同一快照；并发事务只能整体位于快照前或后（撕裂
  测试实证：跨表并发事务的两行都不在 archive 中）。
- archive 只含预期 schema 内的 24 张租户表 TABLE DATA（24 个显式
  `--table=public.<t>` 参数 + TOC 审计双保险）；DDL/FUNCTION/ROLE/ACL/
  SEQUENCE/BLOBS/任意 SQL/未知 schema 对象一律 fail closed。
- manifest：format_version=1、tool_version=p2-02、PG major、schema 
  fingerprint（列结构哈希）、source identity fingerprint（连接坐标哈希，
  供 restore 拒绝 source==target 且不泄漏坐标）、migration 11 条目+
  digest、预期表集合+每表行数、archive SHA-256/size/format/data_only、
  completed。无原始行、无 tenant 列表、无 DSN、无凭据。
- SHA-256 只提供完整性，不提供真实性或加密；本轮不自创加密协议，
  不声称 KMS/envelope encryption/签名/retention/rotation/off-site
  copy/production backup scheduling。

## 8. 凭据与角色边界

- 备份/恢复是显式高权限**离线** operator 行为，与 P2-01 runtime 角色
  严格分离：restore/replay 的目标 preflight 显式拒绝 `trpc_runtime` 
  与非 superuser/BYPASSRLS 角色（FORCE RLS 下多租户 COPY 必须由
  隔离目标上的 migration/recovery owner 执行）。
- `trpc_runtime` 保持 NOSUPERUSER/NOBYPASSRLS/非 owner、不可读
  `schema_migration`；未给 runtime 或普通服务连接增加 BYPASSRLS、表
  ownership 或 DDL 权限；未新增任何普通 runtime 的跨 tenant 函数。
- 数据库密码不作 process argument：工具进程从环境读 DSN（仓库既有
  模式），pg_dump/pg_restore 子进程只拿 PGHOST/PGPORT/PGUSER/
  PGDATABASE/PGSSLMODE + 0600 PGPASSFILE（0700 临时目录、退出即删）；
  Compose 侧密码只走 Docker secret。
- 备份不包含数据库 role password 与外部 Secret Manager value；恢复
  目标使用独立的新 runtime password 与独立 secret provisioning。
