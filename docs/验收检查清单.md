## Admin 对话（控制台 ↔ Agent）

- [ ] **17d. 对话实时回复可见**
  - 用 owner 登录 → 进入「Agent 对话」→ 租户下拉选一个租户 → 选 Agent → 选/新建会话
  - 发送 `只回复两个字：收到`
  - 验证: 自己的气泡立即出现；**Agent 气泡随后出现**（回复经 outbox → stream:outbound → SSE）
  - 验证: 右上角显示「已连接」
  - 说明: 这一条曾经必然失败，根因有三个独立缺陷——`EventSource` 无法携带 Bearer 导致
    `/chat/stream` 返回 401；outbox 因"服务端时间戳 vs 进程时钟"的时区偏差**永不派发**；
    跟随循环反复传 `cursor=$` 跳过调用间隙的消息。三者都已修复并有回归测试/e2e 覆盖

- [ ] **17e. 刷新后仍能从账本回看**
  - 刷新页面 → 在「会话」下拉里选中刚才那个会话
  - 验证: 该轮 USER 与 ASSISTANT 两行都从 `chat_messages`（业务账本）读回并渲染

- [ ] **17f. 租户选择符合角色**
  - owner 登录: 对话页出现**租户下拉**，可切换任意租户（切换后会话与 Agent 列表同步刷新）
  - member 登录: 对话页**没有租户下拉**，显示固定租户标签（`已固定`），只有 Agent 与会话两个下拉
  - 验证: member 直接调用 `POST /chat` 带上别的 `tenant_id` 也被后端钉回自己的租户

- [ ] **17g. 出站可靠性与时钟一致性（回归验证）**
  - 观察 `outbox_events`：正常回合后事件应迅速由 `pending` 变 `sent`
    （`SELECT status, COUNT(*) FROM outbox_events GROUP BY status;`）
  - 验证: 不存在"账本已有回复、outbox 仍 pending、浏览器收不到"的状态组合
  - 验证: MySQL 连接会话时区被钉为 UTC（`OpenMySQL` 注入 `time_zone='+00:00'`），
    使 DB 写的 `CURRENT_TIMESTAMP` 与 Go 写的时间戳表示同一时刻


- [ ] **18. Jaeger 分布式追踪**
  - 访问: `http://127.0.0.1:16686`
  - 查找: 任一 trace，验证链路: `im.callback` → `agent.run` → `tool.call` → `session.*` / `memory.*` → `im.reply`
  - 验证: `trace_id` 贯穿全链路
  - 验证: `session.*` / `memory.*` span 是 `agent.run` 的子 span（阶段 45 起为真实 span，非"并入当前 span"）
