### 10.2A Redis restart failover semantics
Redis restart contract 已由源码和既有 PostgreSQL/Redis lease contract 确定：PostgreSQL `coordination_epoch` 是 authority，PostgreSQL `session_lease`、Queue、Outbox 和 completion rows 是 durable business facts；Redis 保存 owner/fencing token/expiry 以及 trusted epoch 的 coordination lease。Redis restart 本身不 bump epoch；`FailoverStore.Recover` 在 PostgreSQL authority 中 bounded bump epoch 后重新激活 primary。epoch-aware Redis Lua acquire 在 physical key 仍存活但 epoch 已过期时原子接管并递增 fence，new owner 使用独立 client/store bounded acquire/renew，old owner 的 renew/release/validate 被 `epoch_rejected` fencing 拒绝。
Redis stop 后短暂 `redis_unavailable` 属于预期 transport failure，由 lease renewal runner 结束并由显式 recovery path 负责；不是将 `session_lease_lost` 无条件转为 `SKIP`。本轮阶段诊断覆盖 container/network/alias/start/readiness、initial owner acquire/renew、stop/unavailable/restart/readiness、new-owner reconnect/epoch/acquire/renew、old-owner fencing、durable fact check 和 owner cleanup，仅记录 stage/category/success/bounded duration/retries/ownership_verified。
