# P2-01 验收报告：PostgreSQL RLS 与数据库强制租户隔离边界

状态：`P2-01: verified only as a local PostgreSQL RLS and pooled tenant-context isolation boundary`。

## 1. 权威计划定义与最小映射

远端 `docs/implementation-plan.md` 对 P2-01 至 P2-04 仅有聚合描述：
`RLS、恢复、容量、安全、压力和发布运维`。本轮按最小映射写入计划：

## 2. 威胁模型

RLS 防御的是：遗漏 tenant predicate 的 SQL、错误 join、错误 ID 引用、
共享连接池上残留的租户上下文。RLS 不防御：数据库超级用户、migration
owner、宿主机 root、已泄露的 runtime 数据库凭据。自定义 GUC
`trpc.tenant_id` 由数据库客户端可设置，仅是隔离边界，不是认证机制；
服务端仍必须通过 Binding/Identity 与 TenantContext 认证租户。RLS 不
替代入口认证、权限、fencing 或业务校验。Production RLS role/database
rollout: NOT RUN；Compromised database credential/superuser isolation:
NOT PROVEN。

## 3. 角色模型

- migration/schema owner：执行 migration（创建表、policy、函数）、
  拥有业务表；runtime 不得拥有。
- `trpc_claim_owner`：NOLOGIN、NOSUPERUSER、NOCREATEDB、NOCREATEROLE、
  NOINHERIT、BYPASSRLS；不拥有任何表；仅作为三个窄 SECURITY DEFINER
  函数的 owner，并对 `job_queue`(SELECT,UPDATE)、
  `vector_projection_task`(SELECT)、`channel_binding`(SELECT) 持有最小
  DML。
- `trpc_runtime`（runtime application role）：LOGIN、NOSUPERUSER、
  NOBYPASSRLS、NOCREATEDB、NOCREATEROLE、NOINHERIT；不拥有表、schema、
  policy 或函数；仅有 schema USAGE、业务表 DML、窄函数 EXECUTE；
  `schema_migration` 上显式 REVOKE ALL。应用启动执行
  `EnsureRuntimeRoleLimits`：superuser/BYPASSRLS/表 owner 一律
  fail closed（无配置开关可静默接受 owner 连接）。

## 4. 表与策略矩阵

24 张 tenant 事实/协调/派生任务表全部：
`ENABLE ROW LEVEL SECURITY` + `FORCE ROW LEVEL SECURITY` + 单一
`FOR ALL` policy（`tenant_tenant_isolation`），`USING` 与 `WITH CHECK`
均为 `tenant_id = current_setting('trpc.tenant_id', true)`：
tenant、agent_app、channel_binding、user_identity、session、
session_event、message_dedup、memory、summary、artifact、audit_log、
outbox_message、dead_letter、agent_release、tenant_config_version、
coordination_epoch、session_lease、execution_result、job_queue、
channel_binding_audit、vector_projection_task、vector_rebuild_run、
tenant_config_rollout、tenant_config_operation。

豁免表：`schema_migration`（无 tenant 语义的 migration 目录；不对
runtime 授权，owner-only，缺失授权即 fail closed）。缺失/空/非法
tenant context：读返回零行、写被 WITH CHECK 拒绝；无 `OR NULL`、
无 owner shortcut、无 maintenance mode、无基于 caller 字段的宽松 policy。
Down migration 对称删除函数、policy 并关闭 RLS（trpc_claim_owner 为
集群级部署状态，由部署负责删除）。

## 5. 租户事务协议

- 共享 pgxpool 下所有 RLS 表访问必须在事务内
  `SELECT set_config('trpc.tenant_id', $1, true)`（transaction-local），
  由 `storage/tenantctx` 提供：`SetTenantContext`、
  `WithTenantContext`（Begin→Set→fn→Commit；错误/panic/cancel 一律
  Rollback；Commit 失败映射 `ErrTransactionOutcomeUnknown`）、
  `EnsureRuntimeRoleLimits`。
- 禁止 session-level `SET`、SQL 字符串拼接、AfterAcquire 残留或手工
  RESET。Commit/Rollback/cancel/panic/连接复用后 GUC 必须消失
  （测试断言）。
- caller-owned transaction（atomic completion、Memory+vector EnqueueTx、
  coordination write、outbox 各 mutation、configpub mutation）在首个
  业务 SQL 前绑定 tenant；timeout、lock order、outcome unknown、
  retry/DLQ/Ack/Nack、fencing、RowsAffected 判定不变。

## 6. 全局与 pre-tenant 窄能力

三个固定 SECURITY DEFINER 函数（owner=trpc_claim_owner，静态 SQL、
`SET search_path FROM CURRENT`、有界参数与返回、REVOKE PUBLIC、仅
GRANT runtime 角色）：

1. `trpc_queue_claim_next(visibility_micros, delivery_id)`：queue 全局
   claim（recover-expired + SKIP LOCKED + claim 三条语句原样收敛），
   返回被认领 job 行或空。
2. `trpc_vector_task_candidate(now)`：仅返回 `(tenant_id, task_id)`。
3. `trpc_binding_resolve(channel, external_app_id)`：pre-tenant webhook
   binding 解析，仅返回 binding 引用列（无 secret 明文）。

pre-tenant 解析与全局 Receive 各有 negative tests：runtime 仅能执行
上述窄能力，不能读取任意 tenant 配置、content、secret、job 或 outbox。
普通 runtime 角色无任何 BYPASSRLS。Queue/Worker/Completion/Outbox/
Dispatcher 与 Redis fencing 核心算法未改变。
