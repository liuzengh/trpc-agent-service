# 部署说明

## 本地 Compose

```bash
docker compose up -d --build
curl localhost:8080/readyz
curl localhost:8080/healthz
docker compose down
```

默认栈包含平台、Redis 和故障可注入的假模型。Redis 仅在 Compose 网络内暴露。
要使用真实模型，将包含模型配置的 `config.yaml` 挂载到 `/config/config.yaml`。

## 可靠模式

可靠模式以 MySQL 为会话、Inbox、执行记录和 Reply Outbox 的事实源，角色可独立部署：

- `gateway`：接收企业微信、微信客服和 WebChat 消息并持久化；
- `worker`：租约领取消息、执行 Agent、原子提交会话状态；
- `delivery`：投递 Reply Outbox；
- `jobs`：执行知识库索引、摘要和投影任务。

Compose 覆盖文件为 `deploy/compose/reliable.override.yml`，Kubernetes 清单为
`deploy/k8s/21-deployment-reliable.yaml`。

## Kubernetes

```bash
kubectl apply -k deploy/k8s
kubectl rollout status deploy/trpc-agent-service
```

部署前必须替换 `deploy/k8s/10-secret.example.yaml` 中的占位密钥。HPA、PDB、Service
和 Ingress 清单均在 `deploy/k8s/`。

## 可观测性

`deploy/otel-collector.yaml` 提供 OTLP Collector 配置。服务可在 `config.yaml` 中配置
`telemetry.traces` 和 `telemetry.metrics` 使用 stdout 或 OTLP exporter。
